# AllMatters 反馈规格文档

日期为 2026-11-18。本规格依据用户确认的原生反馈界面方案，规定诊断包导出行为，供后续实施和验收使用。当前结论来自源码核查，游戏内交互和文件导出需要在实现后验收。请在实现时尽可能复用原版已有的代码和美术资源。

## 入口与交互

玩家从游戏设置的“发送反馈”打开原生界面。在 Category 下拉框末尾增加一个显示名为 `For AllMatters` 的选项，内部标识使用 `allmatters`，重复打开界面时每次只出现一项。

选择该项后，发送按钮文字显示为 `Export`。玩家填写的文字允许为空，原版输入框的 8000 字符上限继续适用。切回其他类别时，恢复原生按钮文案和对应类别行为。

点击 Export 后同步进入导出中状态并禁用重复点击。一次操作读取当时的文字、两份日志选择结果、环境和局内上下文，之后在后台执行文件处理。场景节点的读取在游戏主线程完成，后台任务持有数据快照。

导出成功后弹窗显示以下原文，并调用系统文件管理器打开最终 ZIP 所在文件夹。

> 诊断文件已生成完毕。请将此文件发给模组作者。

文件管理器支持定位文件时，选中刚生成的 ZIP。文件夹打开失败时，弹窗保留生成成功的结果，并显示可复制的文件位置。只有最终 ZIP 已关闭、可正常读取时才显示成功。

导出失败时保留输入文字、当前类别并恢复 Export 按钮，弹窗简述原因。成功后也保留输入文字并恢复按钮，方便玩家补充现场后再次导出。导出期间关闭反馈界面时任务继续运行，完成结果通过仍然有效的游戏 UI 展示。

AllMatters 分支在原版 `SendButtonSelected` 的发送调用之前接管操作，覆盖到键鼠和手柄共同使用的按钮事件入口。该分支负责本地导出，成功文案明确要求玩家自行将 ZIP 发给作者。分流必须早于原版 `SendFeedbackWrapper` 的空文本检查、全文日志和网络发送调用。

## 输出位置与文件名

最终 ZIP 位于游戏可执行文件所在目录。文件名固定为 `AllMatters_diagnosis_pack_YYYY-MM-DD_HH-MM-SS.zip`，例如 `AllMatters_diagnosis_pack_2026-11-18_14-32-05.zip`。

时间取导出开始时的玩家本机时间，精确到秒，使用公历和固定数字格式。C# 格式字符串为 `yyyy-MM-dd_HH-mm-ss`。

重复点击防护覆盖整次操作的采集、写入、验证和发布阶段。快速完成后同秒再次导出，或其他游戏实例已生成同名文件时，排他创建必须避免覆盖，提示“同名诊断文件已存在，请稍后重试。”并恢复按钮。文件名保持约定格式。

写入权限不足、磁盘空间不足或最终重命名失败时，执行失败路径并报告原因。目标目录仍使用游戏可执行文件所在目录。

## ZIP 内容与格式

一次成功导出在目标目录新增一个最终 ZIP。包内文本使用 UTF-8，JSON 使用可读缩进。ZIP 条目名使用下列固定相对路径，原始账号目录名不进入条目名。

| 条目 | 采集规则 |
| --- | --- |
| `feedback.txt` | 玩家填写的文字，经过 `LogSanitizer.Sanitize` 后写入，可为空文件 |
| `logs/current.log` | 当前运行的 `godot.log`，经过 `LogSanitizer.Sanitize` 后写入 |
| `logs/previous.log` | 上次运行的最近一份归档日志，经过 `LogSanitizer.Sanitize` 后写入 |
| `environment.json` | 自动生成的环境摘要 |
| `context.json` | 可取得的当前局内上下文，主菜单导出时也保留文件并记录局外状态 |
| `collection.json` | 每项采集结果、日志来源和附件缺失原因 |
| `attachments/` | 按故障和数据可用性追加的附件 |

### 两次运行的日志

从游戏实际用户数据目录的 `logs` 子目录获取日志。Windows 常见位置为 `%APPDATA%\SlayTheSpire2\logs`，实施时通过游戏用户目录接口定位。

当前日志取 `godot.log`。上次日志从同目录匹配游戏归档命名的 `godot*.log` 文件中选择最近一份，排除当前文件与其他模组生成的日志。优先按归档文件名中的时间排序，必要时使用最后修改时间并以文件名稳定排序。实现时确认两目标版本的实际归档规则。

读取正在写入的日志时使用允许并发读写的共享方式，并以开始读取时的长度为本次快照边界。日志选择在操作开始时固定，避免写包过程中再次查找导致选到不同文件。

只存在一份日志时导出已有的一份，并在 `collection.json` 记录另一份缺失。两份均缺失或不可读时仍导出反馈文字和环境摘要，逐项记录原因。文件缺失不生成伪造的空日志。

`collection.json` 为每份日志记录包内条目名、来源文件名、最后修改时间和读取结果，来源名称也经过 `LogSanitizer`。两份日志覆盖当前和最近一次历史运行，玩家多次重启后更早的故障需要另行补充历史日志。

### 环境摘要

`environment.json` 按以下字段组织。采集失败的值使用 `null`，具体原因记录到 `collection.json`，避免把未知版本写成有效版本。

| 字段 | 内容 |
| --- | --- |
| `exported_at` | 含 UTC 偏移的本机导出时间 |
| `game` | 版本号、构建提交、运行分支 |
| `allmatters` | 模组标识、实际加载版本 |
| `platform` | 操作系统名称、版本、进程架构 |
| `language` | 游戏当前语言 |
| `mods` | 按实际加载顺序排列的模组标识、名称、版本和来源类型，包含前置库 |
| `settings` | AllMatters 当前生效设置的键值 |

环境字段从游戏当前运行对象和 AllMatters 现有设置机制取得。模组来源使用本地目录或创意工坊等类型值，路径仅在诊断确有需要时作为经过 `LogSanitizer` 的文本进入包内。字段对应的实际 API 在实施前按目标程序集核实。

`context.json` 记录是否处于进行中的一局、单人或联机、房主或客户端、角色、种子、进阶、章节、楼层、房间和战斗回合。当前不可用的字段使用 `null`。本文件描述点击 Export 时的状态，历史日志对应的上一局通过日志调查。

### 按故障追加的附件

首版采用轻量采集规则，自动追加已有且对应当前现场的数据。

- 当前有进行中的一局且存在对应 `current_run.save` 时，追加该文件的副本，以支持读档复现。通过原生保存管理器确认当前模组存档路径，读取现有文件并记录采集时间。
- 当前可取得最近的 AllMatters 异常信息时，追加异常类型、消息和堆栈的文本快照。异常消息和堆栈同样经过 `LogSanitizer`。
- 当前现场有相关联机分歧诊断数据时，追加能够确认与该会话关联的附件。存在嵌套压缩包时，内部文本也必须经过相同处理；相关 API 和文件格式在实施时核实。
- 截图等图片附件沿用原生界面已有的现场数据，在能够取得时追加。玩家负责检查图片中自行展示的个人信息。

每个附件的采集条件、包内名称、成功或缺失结果写入 `collection.json`。实施时若附件格式或会话归属无法核实，记录跳过原因，并保留其余诊断内容的导出能力。

## 脱敏约定

自动脱敏按用户决定统一使用游戏提供的 `LogSanitizer`。所有文本内容在写入 ZIP 前调用 `LogSanitizer.Sanitize(string)`，覆盖反馈文字、两份日志、环境摘要、上下文、采集记录和文本附件。

JSON 在字符串值层面执行 `Sanitize` 后序列化，保持对象结构与原有数字、布尔值类型。可作为存档重新读取的文件，Steam ID 数字字段使用 `LogSanitizer` 提供的数字匿名化接口；目标版本缺少该接口时，使用 `Sanitize` 处理对应 ID 文本并将结果还原为数字，再写回字段，保持同一包内的 ID 对应关系。实施时确认原生存档序列化格式，避免对整个 JSON 文本直接替换后破坏数字类型。

已核实的 `Sanitize` 会替换当前用户主目录的路径写法，并匿名化符合其正则表达式的 SteamID64。用户负责自行检查反馈文字和图片中的其他敏感信息，本规格采用这一覆盖范围作为自动脱敏标准。自动导出使用现有游戏和模组诊断数据，图片附件保留用户自行检查的流程。

## 中间产物与失败恢复

脱敏后的内容直接写入 ZIP 条目。临时压缩文件位于目标目录，使用本功能专用名称并以 `.partial` 结尾。ZIP 写入关闭、可读取验证完成后，以避免覆盖的方式重命名为最终文件。

正常成功和可处理的失败路径都清理本次临时产物。删除失败时显式报告遗留文件位置，下次启动再次清理本功能的遗留临时文件。强制结束进程和断电可能使清理延后到下次启动，清理范围必须能排除其他实例仍在写入的文件。

原始日志、原始存档和截图采集源保留在各自原有位置。临时导出目录和临时原始副本的生命周期由本次操作管理。已有的成功诊断 ZIP 作为玩家此前导出的报告保留。

## 源码核查与兼容范围

本次核实的程序集为项目开发资料中保存的 public v0.107.1 和 public-beta v0.113.1。正式分支后续升级时，按实际发布目标重新核查接口和交互。

| 已核实类型或方法 | 对实施的影响 |
| --- | --- |
| `NFeedbackCategoryDropdown.PopulateOptions`、`CurrentCategory` | 类别由原生下拉框建立；语言不同会影响原版选项数量，应按标识识别新增项 |
| `NSendFeedbackScreen.SendButtonSelected` | 原生点击入口会启动发送任务并禁用按钮，应在此级别分流 AllMatters 操作 |
| `NSendFeedbackScreen.SendFeedbackWrapper` | 两版均先检查空文字，再把描述全文写入日志；AllMatters 分流必须早于这些行为 |
| `LogSanitizer.Sanitize` | 两版均提供此公共接口 |
| `LogSanitizer.AnonymizeSteamIds` | v0.113.1 提供数字形式匿名化，v0.107.1 缺少此接口 |
| `GetLogsConsoleCmd` | 原版收集范围和输出策略需逐项适配本规格，尤其是两份日志、输出路径和附件处理 |

本地方法体证据位于 `.local/api/queries/public-v0.107.1/` 与 `.local/api/queries/public-beta-v0.113.1/`，相关文件名为上述完整类型名加 `.decompiled.cs`。这些本地资料用于实施核查，功能可行性仍需编译和实机验证。

## 验收条件

1. 键鼠和手柄都能选择 For AllMatters，按钮显示 Export；空文字也能成功导出。
2. 两个目标版本分别验证类别切换、重复打开和重新进入设置，新增选项始终只出现一次。
3. AllMatters 导出路径在原版全文日志和网络发送前分流，切回原版类别时恢复其行为。
4. 在游戏可执行文件所在目录生成符合固定格式的 ZIP，时间来自本机；成功弹窗文字逐字符合本规格，并打开所在文件夹。
5. 连续点击只触发一次导出；已有同秒同名文件时报告冲突，已有报告内容保持完整。
6. 验证当前与上次日志均存在、只存在一份、均缺失以及读取失败的情况，包内记录与实际采集一致。
7. 反馈文字、两份日志和摘要中的当前用户目录、符合原生规则的 SteamID64 经 `LogSanitizer` 处理，JSON 与存档仍可解析。
8. 无权限、磁盘写入失败和重命名失败时，输入保留、按钮恢复、临时产物清理结果明确；文件管理器打开失败仍报告 ZIP 已成功生成。
9. 导出中关闭界面后，后台任务和结果提示可完成；强退后的遗留临时文件在下次启动处理，其他运行实例的临时文件受到保护。
10. 在主菜单和局内分别导出，检查环境字段、当前上下文、附件适用条件与缺失记录。双目标编译与针对性自动化验证由实施者完成，游戏内实机验收由用户执行。
