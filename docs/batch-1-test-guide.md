# AllMatters Batch 1 集成测试指南

**状态**: Integration Batch 1  
**包版本**: aeaad43 (2026-11-09)  
**包位置**: `dist/batch-1-integration/AllMatters-public-beta/`  
**游戏版本**: Slay the Spire 2 public-beta (Build 24724944, v0.111.0)

## 概述

本文档指导如何安装和测试 AllMatters Mod Batch 1，包含第 1 批集成功能：

- **#77 (T04 探索)**: 房间探索跟踪和进度计数
- **#78 (T05 商店)**: 商店重访和库存管理
- **#79 (T06 换幕)**: 幕转换、预算清理和终局检测

Batch 1 基于原生拼图系统框架，实现了探索计步、商店库存持久化和跨幕状态管理。

## 安装说明

### 前置需求

- Slay the Spire 2 public-beta 版本（当前安装版本）
- AllMatters 依赖: STS2-RitsuLib 0.6.7
- AllMatters 本体依赖: 在 Steam `data_sts2_windows_x86_64/` 目录下

### 安装步骤

1. **准备 Mod 目录**
   ```
   C:/Users/<YourUsername>/AppData/Roaming/SlayTheSpire2/mods/
   ```

2. **安装 AllMatters Batch 1**
   - 从 `dist/batch-1-integration/AllMatters-public-beta/` 复制所有文件
   - 粘贴到 `mods/AllMatters/` 目录下
   - 包含文件：
     - `AllMatters.dll` (DLL 程序集)
     - `AllMatters.pck` (Godot 资源包)
     - `AllMatters.json` (Mod 元数据)
     - `LICENSE` 和 `THIRD_PARTY_NOTICES.md` (许可证)

3. **安装 RitsuLib 依赖**
   - 确保 `mods/STS2-RitsuLib/` 目录包含完整 RitsuLib 0.6.7 变体包
   - 不要仅复制单个 `RitsuLib.dll`，需要完整包

4. **验证安装**
   - 启动游戏
   - 进入主菜单后查看 Mod 管理器
   - 确认 "AllMatters" 和 "STS2-RitsuLib" 出现在活跃 Mod 列表中

## 测试场景

### 1. #77 探索追踪测试

**功能说明**: 
- 房间完成计数（Steps vs FirstProgress）
- 探索进度跟踪
- 重访商店时不增加 FirstProgress

**测试步骤**:

1. **启动新游戏**
   - 标准角色选择
   - 选择拼图模式（如适用）
   - 进入古代阶段（Ancient）

2. **验证初始状态**
   - 查看左上角进度显示
   - 记录初始步数（Steps = 0）
   - 记录初始进度（FirstProgress = 0）

3. **首次探索**
   - 完成第一个房间战斗或事件
   - **预期结果**: Steps 增加到 1，FirstProgress 增加到 1

4. **重访商店**
   - 使用拼图地图返回之前访问过的商店
   - **预期结果**: Steps 增加，FirstProgress **保持不变**
   - 这验证了重访不触发首次进度计数

5. **继续探索**
   - 完成至少 3 个新房间
   - **预期结果**: Steps 逐个增加，FirstProgress 对应增加

6. **观察进度显示**
   - 在拼图地图上查看已探索的房间标记
   - 验证颜色/标记正确反映探索状态
   - 保存游戏并加载，验证进度持久化

**预期行为总结**:
```
操作                预期 Steps    预期 FirstProgress
初始状态           0             0
完成房间 1         1             1
重访商店           2             1
完成房间 2         3             2
完成房间 3         4             3
```

### 2. #78 商店库存测试

**功能说明**:
- 商店库存持久化（重访后恢复库存）
- 交易原子性（离开商店时取消未完成购买）
- 存档/加载中的库存恢复

**测试步骤**:

1. **进入商店**
   - 探索至商店房间
   - 进入商店界面
   - 记录初始库存（观察可用物品数量）

2. **测试交易取消**
   - 选择购买一个物品
   - **在完成交易前**离开商店（返回拼图或选择"退出"）
   - 重新进入该商店
   - **预期结果**: 该物品**仍显示为可购买**（未售出）
   - 您的金币应返回交易前的状态

3. **测试已售物品持久化**
   - 选择购买一个物品
   - 完成交易（确认购买）
   - 离开商店进入另一个房间
   - 返回原商店
   - **预期结果**: 已购买物品**不再可用**（标记为已售）
   - 您的金币应反映已完成的购买

4. **测试存档恢复**
   - 在商店中购买若干物品
   - 保存游戏
   - 加载该保存文件
   - **预期结果**: 
     - 商店库存状态与保存时相同
     - 已购买物品保持不可用
     - 未购买物品恢复可用（如果您之前离开商店）

5. **测试多次重访**
   - 访问同一商店 3-4 次
   - 每次尝试购买不同物品
   - **预期结果**: 购买历史正确维护，库存状态准确

**已知限制**:
- Native Integration 框架已实现但原生 API 调用为 stub
- 商店库存基于 Jigsaw 节点状态管理
- 多人同步仅单人测试

### 3. #79 幕转换测试

**功能说明**:
- 幕转换时预算和进度清理
- Act 3 双 Boss 顺序（第一 Boss → 第二 Boss 房间解锁）
- 终局检测（击败所有 Boss 后）

**测试步骤**:

1. **完成第一个 Act（古代+探索）**
   - 完成 Ancient 奖励阶段
   - 进行至少 3-5 个探索房间
   - 击败该 Act 的 Boss
   - **观察**: 进度计数、步数、完成标记

2. **进入第二幕（Act 2）**
   - 观察进度显示
   - **预期结果**: 
     - Steps 清零并重新开始计数
     - FirstProgress 清零
     - Ancient 奖励前计数为 0
     - Act 1 的已探索房间标记清除

3. **完成 Act 2**
   - 进行探索和战斗
   - 击败 Act 2 的 Boss

4. **验证 Act 3 双 Boss 机制**
   - 进入 Act 3
   - 完成 Ancient 奖励
   - 进行探索
   - **观察 Boss 房间状态**:
     - 第一 Boss 房间应该**可进入**
     - 第二 Boss 房间应该**禁用**或标记为锁定

5. **击败第一个 Boss**
   - 进入并战胜第一 Boss
   - 返回拼图地图
   - **预期结果**: 第二 Boss 房间现在**可进入**

6. **击败第二个 Boss**
   - 进入并战胜第二 Boss
   - **预期结果**: 
     - 游戏进入终局状态或胜利状态
     - 应显示游戏完成提示或最终奖励界面

7. **验证终局检测**
   - 确认游戏不允许继续探索（所有房间禁用）
   - 显示胜利/完成信息
   - 提供返回菜单或新游戏选项

**预期行为总结**:
```
阶段              进度清理           Boss 房间状态         完成标记
完成 Act 1       ✓ (Steps=0)        N/A                 Act 1 完成
Act 2 开始       ✓ (Steps=0)        N/A                 -
Act 3 开始       ✓ (Steps=0)        Boss 1 可用         -
击败 Boss 1      保持               Boss 2 解锁         -
击败 Boss 2      N/A               N/A                 游戏完成
```

## 故障排查

### 常见问题

**问题 1: Mod 不加载**
- 检查 `mods/AllMatters/AllMatters.dll` 文件存在
- 检查 `AllMatters.json` 文件完整
- 查看游戏日志: `%APPDATA%/SlayTheSpire2/logs/latest.log`
- 验证 STS2-RitsuLib 已安装并激活

**问题 2: 商店物品重复显示或不更新**
- 重启游戏完全加载 Mod
- 删除旧存档，创建新游戏测试
- 检查 AllMatters.pck 文件完整

**问题 3: Boss 房间逻辑错误（两个都可进入或都禁用）
- 这可能是 Native Integration stub 的限制
- 确认当前包版本为 aeaad43
- 查看游戏日志中的错误信息

**问题 4: 进度计数异常**
- 进度应该从 0 开始，每完成新房间增加 1
- 重访不应增加首次进度
- 如果行为不同，检查日志中的"Jigsaw"相关消息

### 日志查询

查看 AllMatters 相关日志:
```powershell
Get-Content "$env:APPDATA/SlayTheSpire2/logs/latest.log" | Select-String "AllMatters|Jigsaw|Shop|Transition" | Tail -50
```

## 修复后新增验证项（Bug#1 & Bug#2）

> 本节对应 **commit f11eb4d**（商店状态持久化修复）和 **JigsawFirstBossReturnsToMap**（Act 3 双 Boss 修复）。
> 本次测试包版本包含这两项修复。

### Bug#1 修复：商店库存持久化验证

**背景**：原实现每次进入商店都重新生成随机库存。修复后应在重访时完整恢复上次离开时的状态。

**验证步骤**:

1. 进入商店，**记录所有可购买物品**（名称、价格、数量）
2. **离开商店**，进入另一个房间
3. **返回同一商店**
4. **核对物品列表**：

| 场景 | 预期结果 |
|------|----------|
| 未购买的物品 | 仍显示可购买，名称与价格不变 |
| 已购买的物品 | 标记为已售，不可再次购买 |
| 存档→加载后重访 | 库存状态与保存时一致 |

5. **反例验证**（确认 Bug#1 已修复）：
   - 第一次访问时，Item A 价格为 150 金
   - 离开后返回，Item A 应仍是 150 金且可购买（不是新随机物品）

### Bug#2 修复：Act 3 双 Boss 序列验证

**背景**：原实现在击败 Act 3 第一个 Boss 后立即触发结束动画（结局）。修复后应返回地图，解锁第二个 Boss 房间。

**验证步骤**（需进入 Act 3，Ascension 10+ 确认双 Boss 布局生效）:

1. **进入 Act 3**，在拼图地图上确认：
   - Boss 房间（第一个）**可进入**（绿色/激活）
   - SecondBoss 房间**锁定/禁用**

2. **击败第一个 Boss**，完成奖励界面
3. **预期结果**：
   - 返回到拼图地图（不触发结束动画）
   - SecondBoss 房间变为**可进入**

4. **进入并击败 SecondBoss**
5. **预期结果**：
   - 触发结束动画/建筑师对话
   - 游戏标记为完成，显示胜利界面

| 阶段 | 预期状态 |
|------|---------|
| Act 3 开始 | Boss 可进，SecondBoss 锁定 |
| 击败 Boss | 返回地图，SecondBoss 解锁 |
| 击败 SecondBoss | 结束动画，游戏完成 |

**反例验证**（确认 Bug#2 已修复）：
- 击败第一个 Boss 后，**不应**出现建筑师对话或游戏结束界面
- 应直接回到拼图地图
