# 你好世界升级调整

日期：2026-10-20。状态：D1–D4 与验收汇总均获用户确认，grill 已结束。代码已实现，用户确认 public-beta v0.111.0 的牌效及升级高亮实机验收通过；验证结果及发布前待验证项见 [验证记录](testing/hello-world.md)。

## 已确定的范围

依据 [v0.1 范围](v0.1-scope.md#你好世界) 和本次用户要求：

- 升级后的你好世界在所属玩家回合开始时生成升级过的随机普通牌；不附加固有，不额外增加单层生成数量。
- 未升级版本保留目标分支原有行为。
- 保留角色原版牌池、解锁与多人限制、游戏 RNG 和生成命令；仅升级生成的实例，不修改牌库模板或其他生成牌效果。
- 目标为 public 与 public-beta；源码检查、编译和真实游戏验收分别记录，不能互相替代。

## 原版依据

现有 [双分支调查](research/dual-branch-api.md#你好世界的实现依据) 记录：两版 HelloWorld 和 HelloWorldPower 的实际实现相同。HelloWorld 每次打出施加 1 层能力；原版升级只添加固有。HelloWorldPower 使用 Counter 叠加，在 BeforeHandDraw 按 AmountOnTurnStart 生成牌；现有能力没有按来源卡升级状态区分层数。

本轮已再次核对两版实际 HelloWorld 与 HelloWorldPower 方法体一致。原版在每次回合触发时只调用一次 GetDistinctForCombat，之后调用 AddGeneratedCardsToCombat；此处是源码证据，不是游戏内验证结论。

2026-10-20 网上查证：灰机 wiki 的[能力牌](https://sts2.huijiwiki.com/wiki/能力牌)与[卡牌](https://sts2.huijiwiki.com/wiki/卡牌)搜索索引均说明，能力牌打出后从本场战斗中移除，不进入弃牌堆，也不视为消耗。直接访问正文返回 403；此处依据可读取的搜索摘要，未声称读取到完整正文。该规则支持本次正常玩法边界，不用于推断所有特殊效果或其他 Mod 的行为。

## 收敛结果

普通来源和升级来源分别累计、分别展示，共同参与一次原版批量生成。生成数量取两类来源在原版回合触发时点生效的层数之和，仅对升级来源份额对应的生成实例执行升级。

两种能力沿用原版回合开始、抽牌前的触发时机；图标拆分不应造成重复生成或额外调用 RNG。对于不符合所属玩家或原版触发条件的情况，保留原版行为。

没有剩余玩法分支待选择；下列验收汇总已获用户最终确认。具体补丁位置、生成结果中升级份额的确定性分配及模型注册方式由实现时核对 API 后决定，不增加按牌强弱挑选升级对象的玩法。

## 验收例子

以下例子针对所属玩家下一次回合开始、手牌空间足够且牌池足以供原版生成流程选取的情况。生成数量受原版牌池与生成命令自身约束；边界情况仍按原版核对。

| 普通来源层数 | 升级来源层数 | 生成总数 | 由本调整升级的张数 |
| --- | --- | --- | --- |
| 1 | 0 | 1 | 0 |
| 0 | 1 | 1 | 1 |
| 1 | 1 | 2 | 1 |
| 2 | 3 | 5 | 3 |

混合来源交换打出顺序不改变生成总数与升级份额。相同牌池、相同生成前 RNG 状态、相同总层数下，批量选牌沿用原版算法；升级处理不额外消耗选牌 RNG。一般实战的出牌顺序可能伴随其他效果，不能据此承诺任何出牌顺序都抽到相同的牌。

两个来源类别共同保留原版一次 GetDistinctForCombat 的去重范围。小牌池或层数超过候选数量时，以原版工厂实际规则为准；不得把方法名直接解释为任何层数下都绝无同名牌。

### 验收汇总（已确认）

| 场景 | 预期结果 |
| --- | --- |
| 普通、升级各一层；连续两个自己的回合 | 每次按两层共同生成，其中一张升级；两个能力图标各显示 1，层数不因生成而消耗 |
| 普通两层、升级三层 | 两个图标分别显示 2 和 3；一次共同生成五张，其中三张升级；不额外触发第二批生成 |
| 打出前升级你好世界 | 产生升级来源能力；本调整不再赋予你好世界固有 |
| 游戏既有重复打出效果使同类来源实际施加两次能力 | 沿用原版每次施加一层的规则，累积为对应类别两层；不额外复制或回收来源牌 |
| 手牌满或空间不足 | 沿用原版 AddGeneratedCardsToCombat 对去向、溢出及相关触发的处理；升级对应的生成实例在交给入牌命令前已升级，不因未能进入手牌而退回未升级状态 |
| 角色、解锁状态或多人条件不同 | 候选牌仍由所属角色原版池及原版过滤产生；只在所属玩家原版触发时点生成 |
| 只有普通来源或其他生成牌效果 | 普通来源保留原版生成行为；其他效果的生成实例及牌库模板不被本调整升级 |
| 同一过程的多人同步与回放 | 两类层数、共同生成的牌及升级份额一致；沿用游戏命令与 RNG，不增加本地独立随机流程 |

以上为验收预期；测试通过的具体范围见独立验证记录。真实联机与回放仍需在完整游戏环境中验收。

单张未升级你好世界正常打出后，产生普通来源能力，来源牌不进入弃牌堆或消耗牌堆。本调整不增加升级或回收这张已打出来源牌的手段；此前提出的“打出后再升级来源牌”不作为正常玩法验收场景。

## 决策记录

### D1：两类来源分别累计（已确认）

用户在第一轮选择 A。每次打出贡献一层；普通来源与升级来源分别贡献生成份额，仅升级来源对应的生成实例获得本调整提供的升级。升级来源不覆盖普通来源的生成份额，也不替换已有层数。

### D2：两个能力图标（已确认）

用户在第二轮 Q2 选择 A。分别显示「你好世界」的普通来源层数与「你好世界+」的升级来源层数；各一层时显示两个各为 1 的能力图标。两个图标共同参与 D4 的批量生成。

### D3：已打出能力牌的正常玩法边界（用户澄清）

用户指出能力牌正常打出后不会进入弃牌堆；同一战斗内仅有一张未升级你好世界时，正常打出后不应存在升级该已打出来源牌的手段。网上规则说明与这一前提一致。因此撤回以“已打出来源牌随后升级”为前提的 Q3，不把用户澄清当作对先前整条推荐（包含重复触发规则）的同意。

本轮设计不新增已打出来源牌与能力层数之间的追溯升级联动。打出前升级、游戏既有重复打出效果等情况仍依照游戏实际流程核对，不以回收已打出能力牌为前提。

### D4：共同沿用原版批量生成（已确认）

用户在 Q4 选择 A。两类来源共同按总层数调用一次原版批量生成，保留同批次去重范围、牌池过滤与 RNG，再按升级来源份额升级生成实例。未采用两个能力分别独立抽取的方案，避免改变去重范围和 RNG 消耗。

## 实现与验证边界

- 先完成普通单层、升级单层、混合各一层的最小闭环，再扩展多层及边界回归。只升级此次生成的可变实例，核查能力展示和实际生成是否一致。
- 在 public 0.107.1 与本机 public-beta 0.111.0 的实际 API 上分别编译；继续复用原版生成及入牌流程。未来版本兼容性以实际验证为准。
- 两版 HelloWorld 与 HelloWorldPower 实现已比对；本轮实现沿用共同 API，分别构建与测试。public 尚无本机完整游戏环境，真实加载及玩法必须标记待验证。
- 本文记录可调整的玩法决定及验收预期，不增加 hash、冻结 contract、baseline 或 gate；不新增 ADR。
- 用户已最终确认汇总并结束 grill，授权 /implement、/tdd、/code-review。测试边界为卡牌公开升级与打出接口、能力公开回合钩子的生成结果和两版真实 API 编译；审查起点为实现前提交 1e3ec0c。当前改动范围集中，不另建 /to-spec；public 真实运行环境缺失单独记录为验收限制。

### 实现选择

- 普通来源继续使用原生 HelloWorldPower；升级来源使用 AllMattersHelloWorldPlusPower。两类能力共存时由原生能力的回合钩子协调一次共同生成；只有升级来源时由其自身钩子生成。
- 原版工厂的惰性结果只枚举一次；按其返回顺序升级前若干张，数量上限为升级来源的回合开始层数。若原版工厂因小牌池实际返回较少的牌，仅处理实际返回实例，不补牌或重抽。
- 通过 CardCmd.Upgrade 在入牌命令前升级实例。两个能力复用原版图像，升级来源以标题“+”及绿色计数区分；中英文说明随 DLL 提供，其他语言的新增说明回退英文，普通来源卡牌说明沿用原文。
