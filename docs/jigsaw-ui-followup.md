# 拼图实机视觉反馈修复（2026-11-07）

起点 `01424f9`，继续 #76、第 1 批（#74、#75、#76）。用户确认上一版节点、连线、持有头像符合预期，自动决定后可正常进入地图；这些确认不扩大为完整玩法验收。

用户提供三张 beta 0.111.0 实机图，指出节点过小、按钮/对白变形、文字位置、帮助期间 ESC 和探索标记问题。新的明确决定覆盖旧的全图拟合要求：**优先节点可读，超出部分通过平移和缩放查看**。不增加密度开关。

## 修改

- 自动相机设置可读尺寸下限（1080p 每格至少 40 像素，720p 至少 30），滚轮/手柄仍可主动缩放，新地图重置相机。纸面内部有独立裁切区域，平移和放大不会把图标画到纸外。
- 结束按钮分配横向宽度并限制高度，1080p 两按钮各 300×88；自动按钮从原生图集按参考的 150 像素左段与镜像右段组合，避免嵌套图集裁切。底部对白与按钮共享固定高度区域。
- 使用参考指定的 Overgrowth 三段纸面、SourceHanSerifSC Medium/Bold、暗底与 event_button 八段边框池卡。帮助框采用原生 VerticalPopup 的 HSV 参数，按 522×600 比例居中；标题、帮助按钮和对白尾巴分别对齐。
- 物理 Escape、原生 cancel 与 pauseAndBack action 共用返回顺序：关闭帮助/重看对白，取消持有或端点，空手时打开原生暂停以保存退出。不会让同一个 Escape 再次打开帮助。
- 普通图标与访问圈使用实际 Sprite2D 子节点；普通可前往节点使用可见的 12% 脉动，访问圈用原生最终帧并着黑色。商店及特殊节点的访问圈排除规则保留。Boss 脉动仍按边界拟合。

## 证据

在既有生产节点和 Godot 输入派发边界验证。`viewport-red.log` 捕捉原按钮尺寸错误，`escape-red.log` 捕捉原 action 无法关闭帮助，`readability-red.log` 捕捉强制微缩；日志位于 `.local/ui-followup/`。

探索测试在领域中实际进入并完成普通节点，检查生产节点树的访问圈与可选节点跨完整周期的缩放变化。这是新的可检查渲染结构及状态证据；原实现使用自绘，没有 Sprite2D，因此该测试的首次失败不能独自证明旧自绘像素完全没有圈。旧版实机未观察到标记的证据仍以用户反馈为准。

纸面资源由界面强引用持有，修复探索截图曾出现的白块；渲染回归在主动资源回收后检查纸面像素仍为暖色纹理。

本轮已成功使用独立 Godot OpenGL 测试宿主渲染生产 UI，无需启动游戏或 Steam。通过 `ALLMATTERS_UI_CAPTURE` 指定 PNG 路径，运行展示专项即可保存编辑、帮助、探索及多尺寸长文案截图。截图和渲染日志保存在 `.local/ui-followup/`。其范围是正式程序集节点与 beta 游戏资源，不含真实游戏 HUD、真实设备或完整游戏加载；无原生 Act 的编辑示例使用 Boss 回退图标，不代替实际 Boss 绑定证明。Mod 元数据等既有宿主提示仍存在。

## 后续实机反馈：标题、原生对白、帮助精简与暂停场景动画

用户确认访问圈已出现，但仍报告普通节点脉动不可见。新增场景树暂停的生产节点回归，原版确因缩放不再更新而失败；界面现用 Always 处理模式，隐藏或进入原生暂停菜单时跳过本地提示计时。这个宿主复现支持修复暂停场景的动画更新，不宣称已独立核实用户游戏中的唯一原因。

帮助只保留“操作与规则”和“返回”，方向导航按实际按钮数计算；拼图结束进入先古/探索时隐藏帮助入口。普通鼠标操作不再绘制手柄网格焦点框，手柄导航继续保留焦点。访问圈规则保留。
