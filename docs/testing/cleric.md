## 自动化入口与证据

`src/Tests/ClericTests.cs` 使用真实注册后的事件模型、BeginEvent、EventOption.Chosen 和原生金币、治疗、选牌、删牌命令，检查状态变化与事件结束。五项行为覆盖：

- 所有玩家均须至少 35 金币；不因牌组没有可移除牌而排除事件。
- 35 金币治疗；83 最大生命名义回复 20；结束后同一选项不能重复结算。
- 金币 34/35/74/75 的按钮条件、不可移除诅咒、免费离开。
- 净化只支付选择者的 75 金币，只移除其选中合法牌；另一玩家不受影响。
- 实际导出的 PCK 加载图片及中英文文本，动态费用与治疗数值正确替换。

这五项在两版目标程序集均通过。首次针对注册、治疗、选项、净化和图片分别观察失败，再补齐实现。大日志保存在忽略目录 `docs/local/test-results/`。

完整回归 `./tools/Test.ps1 -Branch All` 最终通过：beta 20/20、public 20/20（各含既有你好世界 15 项与牧师 5 项）。日志为 `cleric-full-suite-verified.log`。接入时 public 曾出现未生成牌的失败，最终通过先安装已有宿主生命周期替代、再初始化 RitsuLib 修复测试宿主顺序；未修改你好世界业务代码，也未禁用框架补丁。

最终两目标构建均为 0 警告、0 错误，日志为 `cleric-build-beta-final.log`、`cleric-build-public-final.log`。代码审查以用户确认的 `265e961` 为起点，提交前只审查本票暂存改动；Standards 与 Spec 两路独立审查并复核，均为 0 项未解决问题。原有规格草案、范围/计划等未暂存改动不纳入实现提交。

宿主沿用现有战斗状态与空手通知替代，不启动完整房间、网络或回放生命周期。选牌通过原生 ICardSelector 测试入口提供选择；不证明 UI 点击和不可取消按钮已在游戏内验证。图片测试证明纹理从包中加载，不证明实际界面布局。

## 用户通过 Steam 手动验收

按用户要求，实际游戏测试由用户手动完成。当前 beta 开发包已复制到游戏 `mods/AllMatters/`，完整依赖已复制到 `mods/STS2-RitsuLib/`；旧 AllMatters 备份在 `docs/local/game-install-backup/2026-10-20-cleric/AllMatters/`。构建脚本本身不会自动部署。之后若重新构建，退出游戏再复制最新 beta 包。

1. 通过 Steam 启动 public-beta，确认 AllMatters 与 RitsuLib 均加载，日志无依赖或资源错误。不要在需要保留的正式进度中使用调试命令。
2. 进入用于验收的单人游戏；开发控制台输入 `event ALL_MATTERS_EVENT_CLERIC` 可直达事件。此入口绕过自然抽取条件，准入条件由自动化另查。
3. 检查“牧师”标题、图片、三个选项及费用，切换英文后重新进入检查英文。金币不足时检查治疗/净化禁用文案。
4. 在受伤且有至少 35 金币时治疗：扣 35，回复向下取整的 25% 最大生命（实际不超过上限），事件结束并可正常返回地图。
5. 重新进入事件，持有至少 75 金币和可移除牌时净化：扣 75，打开原生删牌界面、只能选合法牌、必须选一张完成；选中牌永久移除，事件结束并可返回地图。
6. 重新进入并离开：金币、生命与牌组不变。记录游戏版本、截图及最新日志；异常时附具体选项与前后数值。

直接启动 EXE 的尝试停在 Steam 初始化失败，未进入事件，不计作实机加载通过。用户已要求后续由 Steam 手动测试；未继续自动启动游戏。

## 用户实机反馈与地图背景核查（2026-10-20）

用户通过 Steam 实测反馈“事件本身与选项效果均没有问题”，截图显示 beta 0.111.0 中文事件图片、选项和金币不足时的锁定文案。用户另确认：牧师图片仅在地图打开时留在地图后方，进入下一节点后消失。

核查该版真实程序集：`NEventRoom.Proceed()` 只启用地图移动并调用 `NMapScreen.Open()`；地图作为覆盖层显示，不替换当前房间。下一节点通过 `NRun.SetCurrentRoom()` 交给 `NSceneContainer.SetCurrentScene()`，后者移除并释放旧场景。因此上述现象符合原生流程，无需增加图片清理补丁。本次采用用户实机反馈与方法体核查，未由 Agent 启动游戏，也未增加不能覆盖实际画面的模型测试。
