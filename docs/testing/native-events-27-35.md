仙馔测试以真实 `CreatureCmd.Damage` 验证 PoweredAttack 和 Unpowered 属性过滤，未分别调度闪电球、毒及卡戎之灰完整生命周期。禁奖使用既有强盗事件战斗房间，包含固定金币、保证遗物和额外药水；不将未实现的 #36 以后事件视为已验收。

关键分支差异：public 骨茶走 `AfterSideTurnStart`，beta 走 `AfterPlayerTurnStart`；历史课复制牌的 public `CreateDupe()` 与 beta `CreateDupe(player)` 分别接入。仙馔伤害钩子的额外 CardPlay 参数也按目标编译。

规范和需求两路独立审查均未发现需修复项；审查后的叙述断言已强化为整段原文仅替换墨水颜色。墨水瓶及病毒余数均通过保存恢复后下一场实际出牌验证。仙馔资格使用 RitsuLib 每玩家 run 数据，经 `RunManager.ToSave` / `RunState.FromSerializable` 恢复，能力消失后仍保持至下场战斗重置。

最终统一验证命令：`./tools/Check.ps1`（脚本语法、Git 空白、两目标全量测试、两目标开发包构建）。结果记录在本机 `.local/checks/last-run.log`。工作区原有 `docs/v0.1.1-scope.md` 的末尾空行会触发 Git 空白检查，执行时仅临时规范该文件末尾，之后恢复原内容；该既有改动不纳入本次提交。

最终结果：两目标各 138 项测试通过，两个开发包构建成功，脚本输出 `AllMatters checks PASSED.`。首次全量执行发现药水未来测试清理 RunManager 时清空本地玩家标识，导致后续光辉出牌异常；现已在三个使用同类清理的事件测试中保存并恢复 `LocalContext.NetId`，原伤害、卡牌及 RNG 断言保留，修复后完整重跑通过。
