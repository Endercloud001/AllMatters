## 实现及验证入口

- 事件只在 Act 2 入池，个人选择按阅读、睡觉、打扫排列。初页、三个阅读结局、睡觉与打扫结局使用本次用户提供的中文；粗体转为原生 `[b]` 标记。睡觉显示 `floor(最大生命 × 0.33)`，83 最大生命显示 27。
- 阅读明确列出五个原版角色，从非当前角色的池取已解锁、符合人数限制的 Common/Uncommon/Rare 牌。合池按模型 ID 去重，使用拥有者 Rewards RNG 逐牌等概率、不放回，最多 20；不足全部展示，零禁用。三个书籍故事使用事件 RNG。生成实例属于拥有者，原生命令加入所选牌一次。
- 两版 `CardCreationOptions.ForNonCombatWithDefaultOdds` 均设置 `NoUpgradeRoll`，故继承 Balance 的普通生成状态，不额外掷升级。抽样不再使用其按稀有度加权的牌厂入口，以满足已确认的合池逐牌均匀规则；也不允许通用奖励钩子扩大已明确限定的角色池、数量或重复候选。
- 打扫使用一次事件 RNG 索引，从“未持有且有合法目标”的瓶子中等概率选择。火焰/闪电/旋风分别绑定攻击/技能/能力；目标没有固有且未被瓶装绑定，选一张且不可取消。
- 绑定通过 RitsuLib 0.6.7 已有 `SavedAttachedState<CardModel, string>` 写入原生卡牌 SavedProperties。保存的是实例附着的瓶子身份，不用牌名、牌组下标或额外身份号定位。三瓶归 EventRelicPool、Event 稀有度，不进入常规、商店或转盘候选。
- 瓶子固有作为 Global keyword 叠加，不写入 Local keyword。战斗副本通过原生 DeckVersion 关联永久牌；局部关键词复制不会将瓶子授予的固有固化到变化产物。失去瓶子清除绑定，自身/升级/其他来源的固有不被删除。
- 永久牌的 IsRemovable 被限制，原生 IsTransformable 因此禁用；直接 RemoveFromDeck 原生命令没有自行检查 IsRemovable，补充绑定检查，避免绕过选牌 UI 删除。战斗副本不受永久牌限制，仍可消耗或变化。

沿用用户已确认的“进入真实事件 → 选择选项 → 检查生命、牌组、遗物、结束状态”入口。没有扩展任意 UI 中间帧保存功能，没有新增 hash、冻结 contract、baseline 或 gate。
