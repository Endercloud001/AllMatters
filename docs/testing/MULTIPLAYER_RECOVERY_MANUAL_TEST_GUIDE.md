# 多人游戏大厅恢复 - 手动测试指南

**适用范围**：#95-96 完成后的人工验收测试  
**目标**：验证多人掉线重连场景下的状态恢复完整性  
**环境**：Godot 4.5.1 + STS2 public-beta 0.111.0

---

## 测试前准备

### 环境检查清单
- [ ] Godot 4.5.1 mono 版本已安装
- [ ] STS2 public-beta 0.111.0 已安装
- [ ] AllMatters mod 已构建 (`./tools/Build.ps1 -Branch public-beta`)
- [ ] 测试 mod 已构建 (`TestMod-MultiplayerRecovery.cs`)
- [ ] HeadlessCombatHost 环境已就绪

### 运行命令
```powershell
# 构建所有依赖
./tools/Build.ps1 -Branch public-beta

# 启动测试 mod 服务器
dotnet run --project tests/MultiplayerTestHost --args "localhost:7777"

# 启动 3 个客户端实例
for ($i=1; $i -le 3; $i++) {
    Start-Process godot -- --path . --resolution 1024x768 --user-dir user$i &
}
```

## 测试场景 1：单玩家重连

**目标**：验证单个玩家掉线 30 秒内重连，状态恢复完整

### 前置状态
1. 启动游戏，3 人进入多人大厅
2. 所有玩家进入拼图，各自收集 2-3 张卡牌，移动 3-5 个房间

### 测试步骤

| 步骤 | 操作 | 预期结果 | 验证 |
|------|------|---------|------|
| 1 | P1 正常游戏中，记录当前状态（房间、卡牌数、金币） | — | ✓ 记录截图 |
| 2 | 强制断开 P1 网络连接（测试 mod 模拟） | P1 客户端显示"连接已断开" | ✓ |
| 3 | 等待 10 秒 | 其他玩家游戏继续 | ✓ P2/P3 未受影响 |
| 4 | P1 网络恢复，自动重连 | P1 状态恢复到步骤 1 的位置 | ✓ |
| 5 | 验证 P1 恢复的状态 | 房间位置、卡牌数、金币与步骤 1 一致 | ✓ 对比截图 |

### 验收标准
- ✅ P1 断线后 UI 显示"已断开连接"
- ✅ P2/P3 继续游戏不受影响
- ✅ P1 10 秒内重连成功
- ✅ P1 恢复位置、卡牌数、金币与断线前一致
- ✅ 探索进度（已访问房间）保留

### 失败排查

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| P1 重连后位置错误 | SaveStateRecovery 未正确恢复 | 检查 LobbyRecovery.GetLobbyState() 返回值 |
| P1 重连后卡牌数不对 | 库存快照损坏 | 查看 SaveStateRecovery.GetSnapshot() |
| P2/P3 也掉线了 | 网络问题而非模拟 | 检查网络连接，单独测试 P1 |
| P1 30 秒后仍未重连 | 超时处理失效 | 查看 IsPlayerRecoverable() 逻辑 |

## 测试场景 2：多玩家同时掉线重连

**目标**：验证网络分区恢复，多玩家同时重连的状态合并

### 前置状态
1. 3 人在拼图中，各自位置不同
2. P1 在房间 5，P2 在房间 8，P3 在房间 3
3. 分别收集了不同数量的卡牌和金币

### 测试步骤

| 步骤 | 操作 | 预期结果 | 验证 |
|------|------|---------|------|
| 1 | 记录 P1/P2/P3 当前状态（房间、卡牌、金币） | — | ✓ 三份截图 |
| 2 | 同时断开 P1、P2 网络（保留 P3） | P1/P2 显示"连接已断开"，P3 继续 | ✓ |
| 3 | 等待 15 秒 | P3 游戏继续，P1/P2 状态冻结 | ✓ |
| 4 | P1、P2 依次恢复网络（间隔 2 秒） | P1 恢复 → P1 状态一致 → P2 恢复 → P2 状态一致 | ✓ |
| 5 | 验证三人状态 | P1/P2 恢复到步骤 1 的状态，P3 继续游戏 | ✓ 对比截图 |
| 6 | 所有玩家进行 1 个房间探索 | 三人的探索进度同步 | ✓ 验证全局状态 |

### 验收标准
- ✅ P1、P2 断线后 UI 显示"连接已断开"
- ✅ P3 继续游戏不受影响
- ✅ P1、P2 分别重连时恢复各自状态（不相互覆盖）
- ✅ 探索进度（已访问房间）三人同步
- ✅ 无状态冲突或重复消耗

### 失败排查

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| P1/P2 重连时互相覆盖状态 | ResolveStateConflict() 逻辑错误 | 检查冲突解决策略（应为服务器优先） |
| P3 游戏进度异常 | 并发修改问题 | 检查并发安全性，锁机制 |
| 探索进度不同步 | 全局状态未合并 | 检查 GetRecoverablePlayers() 是否返回完整列表 |
| 重连超过 30 秒 | 超时逻辑失效 | 验证 PLAYER_TIMEOUT_MS = 30000 |

## 测试场景 3：掉线超时处理

**目标**：验证 30 秒超时后的降级逻辑

### 前置状态
1. 2 人在拼图中
2. P1 进行中，P2 已完成当前房间

### 测试步骤

| 步骤 | 操作 | 预期结果 | 验证 |
|------|------|---------|------|
| 1 | 记录 P1、P2 状态 | — | ✓ 截图 |
| 2 | 断开 P1 网络 | P1 显示"连接已断开" | ✓ |
| 3 | 等待 35 秒（超过 30 秒超时） | P1 超时，显示"会话已过期" | ✓ |
| 4 | P1 尝试重连 | 显示"无法恢复，游戏已结束" 或 "返回大厅" 选项 | ✓ |
| 5 | P2 游戏继续进行 | P2 不受超时影响，可继续游戏或等待 | ✓ |

### 验收标准
- ✅ 30 秒后 P1 显示超时提示
- ✅ P2 游戏不受影响
- ✅ P1 无法恢复已过期会话
- ✅ P1 返回大厅后可重新进入

### 失败排查

| 症状 | 可能原因 | 排查方法 |
|------|---------|---------|
| 超时时间不准确 | 时间戳处理错误 | 检查 `UpdatePlayerState()` 中的心跳时间戳 |
| P1 超时后 P2 也掉线 | 全局状态被清除 | 检查 SaveStateRecovery 是否正确隔离玩家状态 |
| P1 无法返回大厅 | UI 逻辑错误 | 检查超时提示是否提供返回大厅选项 |

## 测试场景 4：状态冲突检测

**目标**：验证服务器状态优先的冲突解决

### 前置状态
1. P1 在服务器上的状态：房间 5，30 金币
2. 由于网络延迟，P1 本地缓存：房间 6，35 金币（陈旧数据）

### 测试步骤

| 步骤 | 操作 | 预期结果 | 验证 |
|------|------|---------|------|
| 1 | P1 断开网络后立即重连（模拟延迟恢复） | P1 收到服务器状态 | ✓ |
| 2 | 等待冲突解决完成 | P1 本地状态被服务器状态覆盖 | ✓ 检查日志 |
| 3 | 验证 P1 最终状态 | P1 显示房间 5（服务器值），30 金币（服务器值） | ✓ |

### 验收标准
- ✅ 冲突时采用服务器状态
- ✅ 本地陈旧数据被覆盖
- ✅ 无重复消耗（如 35 金币 - 30 金币的差额丢失）
- ✅ 日志显示"State conflict resolved: server priority"

## 测试场景 5：探索进度同步

**目标**：验证探索状态在多人间的一致性

### 前置状态
1. 3 人在拼图中，都从 F1 开始
2. 已共同访问房间 1, 3, 5

### 测试步骤

| 步骤 | 操作 | 预期结果 | 验证 |
|------|------|---------|------|
| 1 | P1 访问新房间 6 | 三人都看到房间 6 为"已访问" | ✓ |
| 2 | P2 掉线 5 秒，重连 | P2 恢复后看到房间 6 为"已访问" | ✓ |
| 3 | P3 访问新房间 7 | P1/P2 都实时看到房间 7 为"已访问" | ✓ |
| 4 | 查看"已探索房间"列表 | 三人列表一致：[1,3,5,6,7] | ✓ |

### 验收标准
- ✅ 全局探索状态一致
- ✅ 重连后恢复最新的全局状态
- ✅ 无"重复访问"或"遗漏房间"
- ✅ UI 显示的"已访问/已完成"数量一致

## 故障排查流程

### 第一步：定位问题
```csharp
// 检查日志输出
// 文件：.local/logs/multiplayer-recovery.log
// 查找：
// - [SaveStateRecovery] 初始化消息
// - [LobbyRecovery] 连接事件
// - 任何错误或异常堆栈
```

### 第二步：检查数据一致性
```csharp
// 获取当前大厅状态
var lobby = LobbyRecovery.GetOrCreate(runState);
var state = lobby.GetLobbyState();

// 检查三个恢复信息
Debug.Log($"SaveState: Act={state.SaveState?.Act}, Steps={state.SaveState?.Steps}");
Debug.Log($"ExplorationState: Visited={state.ExplorationState?.VisitedCount}");
Debug.Log($"LobbyReady: {lobby.IsLobbyReady()}");
```

### 第三步：隔离变量
- 先用 2 人测试，再升级到 3 人
- 关闭其他系统（Hunt/Battle），专注于恢复
- 使用测试 mod 精确控制断线/重连

### 第四步：采集证据
- 截图（断线前后状态对比）
- 日志（完整的恢复过程输出）
- 网络包捕获（可选，用于网络层问题）
