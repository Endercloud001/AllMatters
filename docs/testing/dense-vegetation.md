# #38 茂密的植被：开发与人工验证

日期：2026-10-27。需求：[issue #38](https://github.com/Endercloud001/AllMatters/issues/38) 与父规格 #26；审查起点 `39e9307`。

## 开发过程

检查时已有未提交的植被测试草稿及测试入口，生产实现尚缺失。补齐原生 DenseVegetation：加入第一、第二幕事件池，调用原生休息处行动生成器，排除愈合、孵化与不可用项，通过事件 RNG 不重复抽取至多三项。候选随当前事件实例保留，取消选牌不重抽；成功执行一次后只留下原生战斗入口，微型帐篷不能增加次数，旧选项不能追加结算。

直接执行所选行动的 OnSelect，保留治疗、锻造等各自钩子及原生选牌/奖励命令；不依赖休息处房间假装执行成功。中文、英文选项复用原生行动说明与实际数值，附加进入战斗提示；动作后的叙述使用通用休整文案。跋涉继续使用原生 61–99 金币及失去 8 生命，战斗、怪物、奖励与素材沿用原生资源，没有新增美术资源。

双轴审查首轮：Standards 0 项，Spec 发现两项多人同步缺陷（不同玩家候选索引不一致、取消选牌后页面分叉）。修正为多人只从全队均合法的行动交集中抽样、统一索引，每人仍执行自己的原生行动对象；每次访问仅生成一次各玩家行动，新访问重新检查资格。多人投票确定升级/烹饪后选牌不可取消，单人仍可取消重试。新增回归从原生事件同步器发本地票、注入远端网络消息，保留消息缓冲/投票/共享执行链路，验证两种选牌行动均到战斗页、仅开战一次及再次进入时更新资格。

双目标源码核实：切肉刀烹饪在 public 0.107.1 增加 9 最大生命，在 public-beta 0.111.0 增加 5，分别保留该版本规则。测试从最初“没有候选”的失败补齐到玩家生命、牌组、遗物、取消选择、战斗入口、房间恢复与双语展示等结果断言。

## 人工安装与验收

退出游戏并备份现有 Mod。根据游戏分支复制对应开发包至 `mods/AllMatters/`；完整 RitsuLib 包另放 `mods/STS2-RitsuLib/`，不能只复制 compat DLL。由用户通过 Steam 启动。

- public 开发包：`E:/Godot_v4.5.1-stable_mono_win64/sts2mod/AllMatters/dist/public/AllMatters/`
- public-beta 开发包：`E:/Godot_v4.5.1-stable_mono_win64/sts2mod/AllMatters/dist/public-beta/AllMatters/`
- 独立依赖：`E:/Godot_v4.5.1-stable_mono_win64/sts2mod/AllMatters/.local/dependencies/RitsuLib-0.6.7/`

1. 第一、第二幕分别进入植被：默认显示治疗、升级与跋涉；携带行动遗物时至多三种休息行动。持有蛋、多人同行时也不出现孵化/愈合；没有可升级牌时不出现升级。中文、英文说明均应显示对应行动与战斗提示。
2. 最大生命 80、当前生命 10 时，普通治疗到 34，持皇家枕头到 49。升级只升级指定永久牌、不治疗；取消选牌应返回相同候选，仍可重新选择。
3. 分别携切肉刀、铲子、佩尔的增生组织、壶铃、南瓜蜡烛验烹饪、挖掘、复制、举重、添火：核对牌组/遗物计数与原生说明，完成一次后只剩“进入战斗”。烹饪分别核对 public +9、beta +5 最大生命。多人中只有全队均可执行的行动会被抽取；仅一人有铲子时不出现共同挖掘，一人无升级目标时全队不出现升级。共享投票确定升级/烹饪后，各玩家必须完成选牌，不能单独取消造成页面分叉。
4. 携带微型帐篷，完成一次休息后不能再选其他行动；动作效果完成前不得开战。点击战斗只进入一场原生植被战斗，结束与奖励保持原版。
5. 选择跋涉，核对获得显示的 61–99 金币、失去 8 生命并结束；重复点击不重复支付或奖励。多人中核对每位选择者的效果归属，不串改队友牌组/金币/生命。
6. 在游戏允许的时点保存、读档及回放，核对候选、金币、已完成动作和战斗不重抽、不重复；真实联机核对共享选择、战斗同步与中断恢复。记录游戏版本、语言、人数和截图/日志，未执行项保持待验状态。
