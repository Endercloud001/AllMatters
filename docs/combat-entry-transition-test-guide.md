# 普通节点进入过场验收

本功能复用游戏原版房间过场，覆盖拼图探索中的普通节点进入，包括战斗、事件、问号、商店、休息点及宝箱。保留原有选点、扣步、保存和共同就绪流程；动画不能消除原生加载或 GC 开销。当前实现与包的实际验证结果见同目录实施记录和交付目录的 `delivery.md`。

## 安装与恢复

退出游戏，保留当前普通包、诊断包和测试存档。按当前游戏分支选择 `dist/combat-entry-transition/AllMatters-public-beta/` 或 `AllMatters-public/` 的完整五文件包，手动替换 `mods/AllMatters/`，不要同时保留两份 AllMatters。仍需相匹配的完整 RitsuLib 0.6.10；此包不捆绑依赖。Agent 不启动游戏或向安装目录复制文件。

这次使用普通构建，不包含临时性能采集器。若之后继续性能定位，请勿用旧采集包与本次普通包的视觉差异冒充同一构建的性能对照；旧采集数据保留用于原因调查。回退时退出游戏，再手动换回保留的完整五文件包。

## 单人

1. 在原来的拼图测试存档进入已完成编辑的探索地图，选择普通战斗，观察地图至房间切换：先出现原版房间过场，随后才露出目标房间；中间不应闪现旧房间。
2. 再进入事件、商店及其他可达房型；问号不需预先知道实际房型。各次只扣一次步数，奖励、库存、房间内容和战后回图照常。
3. 淡出期间尝试重复点击目标与快捷键，不应重复进入、扣步或播放叠加音效。结束后确认地图/房间按钮与手柄焦点仍可用。
4. 分别用游戏 Normal、Fast、Instant 偏好尝试。Normal/Fast 的扫屏与淡出会占用时间，不是加载提速；Instant 沿原版偏好，不预设一定全黑或零时延。记录实际结果及所用分支，不擅自把等待动画解释为主线程卡顿。
5. 保存退出、重新继续，确认读档/幕入口等原有过场和恢复不重复播放或长期黑屏。已有战斗开始横幅由原版管理，不额外生成。

## 多人及退出

1. 各端使用同一游戏分支及本次完整包。本功能新增了本次进入的过场就绪消息，多人不得混用旧普通包、旧采集包或其他消息集不同的构建。全员投票确定目标后才开始本次节点进入过场；单人投票不应直接切房。
2. 尽可能覆盖一端较慢的进入：快端应继续等待共同就绪，不能因自身淡出完成而提前露出房间或允许操作。
3. 检查同选与分选、问号实际战斗、商店重访；目的地决策仍由现有拼图投票规则决定，过场不另抽目标。
4. 在进入中退出/断线，再按原有恢复流程加载。失败时应能回到可操作的地图或现有恢复入口，不长期黑屏、不重复结算；旧会话的迟到操作不能改变新会话的画面。

## 反馈内容与证据边界

反馈游戏分支、人数、房型、Normal/Fast/Instant、是否首次进入，以及具体异常（旧房闪现、重复淡入、黑屏、输入未恢复或扣步异常）。截图或短录像能帮助判断视觉顺序，勿发送账号信息或完整存档。

自动测试可核验生产入口、原生就绪/恢复与过场调用时序；TestMode/headless 不验证实际扫屏渲染、GPU 平滑度、真实 Steam 多端或所有分辨率。人工通过只按用户实际反馈记录，不推断 #81/#94 的其他未验收场景已经通过。
