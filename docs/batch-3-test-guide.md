## 三端操作与预期

每项记录游戏分支、人数、Host/Client、存档阶段、输入、结果及日志路径。分别执行 public 与 public-beta；不能用一版结果代签另一版。

1. **生成与布局（#96/#81）**：三人进入拼图，手动摆放并执行自动生成；覆盖不同幕、预算和七种形状。检查边界和连接、可达房间与 Boss 路径；生成失败仍可撤回/重做。生成进行中退出后从原存档新建加载大厅，确认池、摆放、预算与操作输入恢复，旧任务不会覆盖新会话。
2. **加载大厅（#91）**：原三人存档先仅两人加入；第三人稍后加入，再尝试加入后离开。全员准备前显示实际在局名单，原三人的角色及完整库存仍保留；陌生角色不能顶替。分别从编辑、生成、Ancient、探索、已访问和待进入阶段开始。
3. **共享展示（#92）**：加载后比较三端共享访问圈、完成标记、当前位置、步数和追猎提示。通过正式 UI 继续一次探索，三端结果相同；缺席者不产生个人访问分叉。
4. **完整保存与奖励（#93）**：使用升级牌、特殊牌状态、遗物、药水、金币的存档。让一人先领取 Ancient 后 Host 退出：重新加载应整体回选择前的完整点，并保留成功地图。全员领取后保存重载：奖励不重发。两人在局时完成奖励，原缺席者在后续加载大厅回归后检查其应得奖励及已领者库存、生命与随机状态。
5. **目的地与可靠进入（#81）**：客户端先点节点，节点旁显示该玩家头像；房主未投票时保持原地、不扣步。改投时头像移到新目标。全员票齐后，同选直接进入，分选按每位玩家的一票随机决定，重复同目标增加权重；全队进入同一房间，仅可靠就绪后扣一步。分别验证确认前失败后的重试/放弃、确认后个别端失败以及迟到/重复消息；不得断开成单人或重复扣步。
6. **真实商店重访（#81/#93）**：购买卡/遗物/药水、使用删牌并记录折扣、售价、售罄状态；离店重访并保存加载。库存不重抽，已买物品不再出售，后续真实购买仍正常。Unknown 实际开出的商店也能重访。每次进入保留原生房间历史，但重访不增加首次进度、爬层分、取得层数或误触 Juzu/LanternKey 条件。
7. **组合恢复（#94）**：交叉执行六个阶段 × 全员/缺席/迟到/离开，共 24 种组合，比较完整地图与玩家库存并继续实际操作。补测 Host 在部分领奖、生成进行中退出、自动生成失败、连接中断；检查恢复后继续、放弃和正式 UI 输入，而不只看大厅人数。

运行中热重连、Host 迁移和跨游戏版本联机不属于本轮承诺。上述失败分支应在可控测试环境进行；若出现损坏或来源不匹配，应明确拒绝并保留原存档，不应静默重造数据。

#92 本轮恢复的是既有 `Steps/Budget` 步数违限投影。面具发放、根房安全、战斗增强和最终 Boss 后清除属于后续 #84/T09 追猎接入，本批不把步数恢复当成完整追猎机制已实现或验收。
