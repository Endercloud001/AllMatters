## 一种具体可证明保底池族

以下是存在性证明与候选技术构造，并非要求玩家少用块，亦非已决定固定Boss总在I形的产品分布。

选一块I形作为Boss块，骨架从左到右编号a,b,c,d，内部仅链ab,bc,cd。全池仍保留七形各两块。先古中心(0,0)。单Boss：a=(3,0), b=(6,0), c=(9,0), d=(12,0)，d为Boss；a/b/c为普通节点。双Boss：a=(3,0), b=(7,0), c=(11,0), d=(15,0)，c/d为第一/第二Boss。先古只接a。仅使用该块，其余13块留池中。

核对：普通a与先古3×3右边界x=1之间只有空格x=2；内部间距分别统一3和4；单Boss占x=11..13，与c=9间空x=10；双Boss占x=10..12和14..16，中间空x=13。所有通路同一直线且相邻段只在共同端点相遇，互不压普通或大节点；Boss无跨块边，单Boss度1，第一Boss度2/第二Boss度1。去掉Boss后普通子图仍连通。单Boss距离4、双Boss第一Boss距离3，均≤13≤14≤15。旋转整张见证四种方向仍成立。不声称这些极短路线有好的体验。

房型补池也可以有确定保底，不能“shuffle直到过”：十四块中的两I、两O均选四节点Hamilton路径；另十块任取生成树。各树选择独立集，共至少28个位置（树二分较大侧≥2/块），放置14个特殊标签（4商店+6休息+4宝箱），特殊标签之间无内部边，因此自动满足同类不相邻。剩42位置放20普通战斗+16问号+6精英，配额恰满。为了上述I见证，将Boss I四位置全部预留为非特殊；其他13块的独立集容量至少26，仍足够14。先为四预留位分配普通战斗，再分配其余；之后替换I末端一/二节点为Boss（符合替换来源）。这严格遵守先配普通房型后替换Boss，替换后56不增。此为有偏但有限步可完成的合法池构造，不是所有随机分配均可延拓的证明。候选配额若改变须重算独立集容量，不允许静默裁减配额。

## 无边界网格的有限性证明

以下为本项目推导，前提：内部连通、每条跨块边水平/竖直、实际边界只留一空格、中心均整数、大节点半径≤1、每块4节点且骨架四连通、间距≤4。

每块任意两节点中心的L∞距离≤3×4=12；任意合法外部边两端中心距离≤4。对提交后的连通布局，碎块收缩成图，加先古为根，选一棵生成树。根到任意碎块最多14条跨块边，每次跨边最多4，块内从入口到出口最多12，故任意节点中心距原点L∞≤14×(4+12)=224。含节点占地的保守坐标盒为[-225,225]²。该盒是数学搜索界，不是玩法边界；不可拿它拒绝玩家正在编辑的孤立远处块，孤立块提交时另按规则撤回。它比任何实用搜索窗口大得多，但为有限完全搜索提供依据。

更实用的枚举：从先古已连接集合逐块添加，每次遍历未用块、四旋转、选其某普通端口和已放块某普通端口/先古端口及方向。距离固定后锚点平移唯一。先做局部占地/通路/端口检查；保留候选外部连接或枚举其子集。每块内部连通，任意最终合法布局的收缩图存在根生成树，故其块存在一种这样的加入顺序。要声称完备，不能仅保留某个贪心顺序，必须枚举所有可选块、端口、旋转及边子集；只能对完全相同几何/标签/内部图的对称状态去重，不能把同形异房型块合并。

## 检查与搜索表达

块数据为四个局部整数坐标、节点房型、固定边列表、锚点编号。四旋转用(x,y)→(-y,x)，乘2/3/4间距后整体平移；不能在旋转后单独压缩Boss附近间距。节点占地为闭整数格集合；通路为两个边中点之间的水平/竖直段，截去端点占地。几何段相交须区分共同节点端口与无关交叉，不能仅检测通路中心格：相邻格共享边界的画法和实际格占用应统一。可用精确整数/加倍坐标表示边界半格，免浮点容差。

外部边作为可选择布尔项，不把接近自动视作连边。预计算候选边要求水平/竖直、间距合规、端口空闲、Boss排除；两块最多两边。每个选中块的四节点整体选中，不能只选Boss和一节点而丢掉同块另两节点。固定内部边不允许求解器为消除冲突删改。同房型限制只对内部边生效。所有选中节点与先古连通；移除所有Boss后每个普通节点仍与先古连通；另核对Boss内部邻接集合精确等于单叶/双链，而非仅度数上界。

完整验证器先核对池/块身份及固定内部数据、合法旋转，再检查实际空间和全部通路、端口、计数、Boss、连通性、Boss移除后的普通可达，最后对合法图从先古BFS到第一Boss。最短路≤额度足以给一条按时路线，因为依次首次进入路径上节点各计一步；反向任意按时探索至Boss，其新增节点序列必须从已完成区域逐个扩展，得到一棵至Boss路径不长于已花进入数。免费中转或商店重访不能省掉首次探索的中间节点。

节点≤57，内部边每块≤4，外部边候选≤O(57²)。朴素空间检查O((V+E)²)，BFS O(V+E)，本规模足够先保正确，后按需要用占格索引优化。搜索则指数级：粗略有限盒内每块候选≤4×449²，加不用选项，14块笛卡尔积已不可直接穷举；还要选择跨块边。根扩展比笛卡尔积强很多，但仍无交互时间上界承诺。最小剩余候选、碰撞前向检查、Boss先选、乐观最短路下界可剪枝；乐观图不可达才可判该分支失败，不能拿当前未完图不可达剪掉所有未连接Boss。

## 推荐及状态语义

推荐无外部求解器的混合：先构造并验证池及同池见证，发池后不再改变房型/内部图；自动时在工作副本中按确定预算搜索更丰富布局，每个完整候选走独立验证器；预算到达返回保留见证。不要无限重随机池。若见证不存在或验证失败，视生成错误，恢复原布局而非偷偷重新发池。

“已证明有解”适用于上述受控池族及保留且通过验证的具体见证；“实验找到解”适用于某给定输入的一次搜索见证，不推出全部种子；“预算耗尽未找到”是UNKNOWN，不是UNSAT。有限完全枚举穷尽、或正确完整模型返回INFEASIBLE才能对该输入给出不可解结论。CP-SAT返回FEASIBLE须再过项目验证器；模型遗漏约束不能靠求解器弥补。AddHint也不强制返回该解。

给定任意外来/恢复的池，不应假定上述受控族保证；先核对保存见证与池一致，无法复用时搜索到预算仍无解必须明确失败。用户已有布局只是搜索偏好，自动全员确认已授权重塑；整个生成期间不对已接受布局原地修改。成功统一替换，失败保留原图原池原边。手动提交失败保留自动撤回结果，与自动失败语义不同。正常退出在生成阶段恢复重跑，成功后保留已确定图，不重新随机，具体存储交集成方案。

可重现输入须包含规则/算法版本、池完整数据（稳定块/节点身份、房型、内部边、Boss次序）、幕/额度、初始seed、稳定候选排序、RNG实现和调用顺序；预算采用扩展次数等确定计量。时钟超时可保用户体验，但其发生点不应决定持久结果；多线程竞速不能承诺跨机器同图。恢复时以原池原seed从头重算，或使用已保存合法结果，不从不完整内存继续。

## 仍须原型验证

选择混合的安全性不依赖性能实验，但多样性/操作时间尚无证据。后续最小原型输入单/双Boss、三幕额度、受控随机种子至少1000，以及人为冲突的池和已编辑布局。指标：每池验证/见证成功率、搜索扩展数/耗时p50/p95/max、回退比例、实际使用块数、Boss路径长、方向/形状偏置、重跑一致性。失败判据：一例非法成功、同池见证丢失、修改用户原图后失败、超预算不中止、同确定输入不一致，均阻止升级为正式实现。用户已明确要求满额度探索机会，旧单块保底不再允许自动回退；后续仅验证合格布局的房型、多样性和Boss I集中等体验。不擅自增加Boss最短距离下限。
## 用户新增自动条件：充要定理与线性探索见证

2026-11-03 后续用户批准的玩法修订，覆盖本文前述自动推荐中的旧验收条件；手动提交保持原规则。设幕额度B≥1，要求自动布局存在一种走法：前B−1次进入恰为B−1个不同非Boss碎块节点，第B次进入单Boss或第一Boss。先古之民不计入B−1；不以商店重访充数。不要求所有走法都满足，不禁止更早抵达Boss的捷径，不要求长度B的简单图路径。

以下为本项目规则上的数学推导，不归因于Knuth或OR-Tools，不需要求解器。前提是布局已通过所有既有空间/内部图/连边/Boss结构合法性检查，且删去所有Boss后剩余图H包含先古s及全部N个普通碎块节点并连通；Boss进入在玩家选择后发生，不因相邻而强制进入。令t为单/第一Boss，d为原合法图G中s到t的最短边数。则新增条件等价于：

`N >= B−1 && d <= B`。

必要性：B−1个不同非Boss碎块节点当然要求N足够。它们依探索规则从已完成区域扩展，因此与先古形成连通子图。第B步能进Boss，意味着该区域包含t的一个普通邻居；取此区域内从s到该邻居的一条简单路再接t，长度不超过B，故d≤B。免费中转不影响此前已花掉的首次进入数。

充分性：取s到t的最短路，把最后Boss端点去掉，得到s开始的普通前缀P，共d−1个普通碎块节点。双Boss的第二Boss是终端，最短路不需要经过它；沿P顺序首次进入并完成其普通节点，此时已完成集合C连通且已含t的普通邻居。因为d≤B，已有普通数d−1≤B−1。若尚不足B−1且N≥B−1，H的连通性保证C必有一个尚未进入的普通邻居；选择它首次进入并完成，C仍连通。重复到B−1个普通节点后，t仍邻接已完成区域，故第B次可选择进入t。这一构造允许从其他已完成支路免费中转，完全符合当前探索规则。

```text
ExactBudgetOrder(G, B):
  require existing layout validation, including connected H = G minus all Bosses
  t = single Boss or first Boss
  if count(H minus {s}) < B - 1: reject
  BFS in G from s, retain parent and shortest distance to t
  if t unreachable or distance(t) > B: reject
  order = shortest path s->t, removing s and t  // only ordinary fragment nodes
  C = {s} union order
  // order itself is already a legal first-entry sequence
  queue = every ordinary vertex in H\C adjacent to C, each queued at most once
  while length(order) < B - 1:
    v = pop queue
    append v to order; add v to C
    enqueue every neighbor of v in H\C not queued before
  return order followed by t
```

初始化C是在算法内标记构造出的顺序前缀，并非跳过游戏中的实际完成。队列只放邻接已完成集合的节点，出队后其父邻居永不移出C，故所有后续选择始终合法。BFS、前缀回溯、队列初始化与扩展总共O(V+E)时间、O(V)空间；无需展开免费中转路径，也无需每次重新扫描全图。邻接表按已有稳定顺序遍历即可得到确定见证。若只需布尔判定，已有验证器确保H连通后，统计N并BFS即可。

边界：B=1时仅需s直接连接t；实际Boss禁跨块，现规则不会出现这类合法图，判定自然失败。N=B−1时扩展可用全部普通节点；d=B时最短路前缀已恰好足够，不扩展。短路d≪B并不违法，支路可补首次进入数。双Boss不计第二Boss作普通节点，也不将其作为可中转节点。若以后引入强制传送、普通房间阻止完成或改变已完成区域扩展，此定理须重新核对；它只证明地图探索顺序存在，不保证玩家能赢得每场战斗。

**旧保底失效与修复边界**：单块单Boss仅N=3、双Boss仅N=2，当前B=15/14/13时均不满足N≥B−1。它们仍是旧规则/手动合法性示例，不能作为新增自动条件下的池可解保证或搜索回退。自动造池必须构造并保留至少B−1个可达普通碎块节点、且d≤B的完整布局见证；不得在给池后偷偷增加块或改房型。保留见证、预算搜索、独立验证的混合架构不变，但见证验证必须加入本定理的条件及探索顺序，不再只验BFS上界。满足更强自动条件的布局自然仍满足手动旧条件；手动提交不能反向套用N≥B−1而误拒旧合法布局。

该结论是解析证明，非“实验未遇反例”；实现仍应测试分支图而非只测长链。典型验证输入应含：短Boss捷径加足够支路（通过）、长简单路不足B但普通总数足够（仍可通过）、N=B−2（拒绝）、d=B+1（拒绝）、双Boss第二Boss不可充数、普通区不连通（由旧验证拒绝）、以及分别B=15/14/13的边界。最长简单路径的NP困难不属于这个新增条件，不能据此升级搜索成本或引入求解器。
