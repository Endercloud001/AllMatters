## 4. 验证层级、实施阶段与责任约定

最高层能回答问题的可运行 Interface 优先：

- **D：跑局行为**——提交玩家意图/原生结果，经四个 Module 的公开 Interface 观察共享状态及效果；回答规则组合和事务结果，不依赖UI内私有字段。
- **N：原生Adapter宿主**——调用目标实际DLL、Godot/Ritsu、原生命令/房间/保存流程；记录替代了哪些IO/资源/readiness/网络。能由这里回答的事实由Agent执行，不转给用户。
- **G：正式Godot界面/后台任务**——真实节点树、输入路由、原过场及任务；纯模型/浏览器不足以回答此类问题。
- **M：正式游戏多端/大厅**——同版本真实端、原生传输/大厅和真实必要同步；注册/TCP/多人参数不足以回答。游戏/Steam安装启动及真实端操作由用户手动完成。

这些是证据层级，不要求另建框架或替换已选seam。对一项问题，选择可实际回答它的最高层运行入口；下面矩阵的“D→N→M”表示复用普通行为测试、补真实Adapter、最终端到端，不能以低层代签高层。

阶段：**T1** 正式Module实现时；**T2** 对应Adapter和可安装集成包接入时；**T3** 正式双版端到端/用户验收时；**T4** 正式发布准备时的兼容声明与资源责任。它们表达实施触发条件，不是本地图新增 gate。
