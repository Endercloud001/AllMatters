## 将五个问题分开

1. **造池**：先选合法的骨架/内部边/Boss位置与房型赋值，再补齐库存；形状数量、房型配额、Boss替换前后统计分别检查。不以随机尝试最终成功代替保证。
2. **保证池有解**：池在交付前必须附带一份用本池节点ID构成的合法布局见证；独立验证通过才接受。见证是普通布局数据，不新增hash、contract或gate。仅证明存在，不要求所有池节点都摆出。
3. **给池自动摆图**：先取对应有效见证作保底，再以有限预算回溯增加/替换碎块、换朝向、选择跨块边，择一个验证通过的候选。只能移动/选择原池块，不能重骰内部边/房型。任意外来池无见证时可求解，但预算耗尽不能报无解。
4. **验任意布局**：不信任生成器的推导；从池与布局重建空间、通路、图和Boss结构，最后才运行限步BFS。
5. **失败与恢复**：成功候选在临时数据里构造并校验，统一接受后才替换旧布局。预算、取消、异常均有确定出口，正常路径绝不无限重抽。

## 比较与推荐

| 方案 | 有解保证 | 成本与边界 | 判断 |
| --- | --- | --- | --- |
| 先构造布局再补池 | 从合法见证推出池有解；必须构造整块，不能任意切图后称四格骨架 | 小构造可线性完成；分布偏向所选见证，可能路线过短 | 用于造池及保底 |
| 先随机全池再回溯/CSP | 找到且验过解才证明该池有解；完整有限域穷尽才证明无解 | 平移、旋转、子集、连边组合指数爆炸；超时只是未知 | 不作唯一保证来源 |
| 约束求解器 | 可建模条件选择、几何冲突、端口与流连通；仍需有限域 | CP-SAT等有依赖及C#部署成本；全域编码比14块专用搜索复杂 | 研究/离线对照候选，不要求正式引入 |
| 构造见证 + 有界增量搜索 + 独立验证 | 始终保留已验证见证；搜索失败回退它 | 不保证最优、多样性或用满池；搜索预算可控 | 推荐，符合不改玩法的最小依赖方案 |

算法一手来源、准确实现位置及许可见[算法来源比较](v0.1.2-jigsaw-algorithm-sources.md)；构造证明见[构造有解见证](v0.1.2-jigsaw-constructive.md)；Mysterious Map与验证细节见[参考实现审计](v0.1.2-jigsaw-reference-audit.md)。推荐是本票技术决策，路线长度与多样性仍须体验验证；不额外规定最低路径长度或必须使用多少块。

## 无界地图的有限搜索

固定起点消除平移自由度。任何提交布局的碎块图连通，每个新块可沿一棵碎块生成树接入已有集合；因此可以穷举“剩余块×四旋转×已有普通点/起点×新块非Boss点×四方向”求唯一平移，使占地间恰留1格。这里只枚举接入所需边，其他可选边随后枚举；不要求玩家编辑也按连通顺序。

完整搜索需回溯生成树接入顺序与候选边，而不能贪心固定第一条接入边；允许停止在任意含Boss合法子集。所有形状旋转和节点数有限，至多14次接入，故此枚举有限。包含环的合法布局也有生成树，不因增量顺序漏掉；额外边不影响已有空间合法性，最后添加并检查配额。固定原点下每次跨边中心距至多3（Boss无跨边），块内锚点到任一点曼哈顿距至多3×4=12；粗界每次锚点增量≤12+3+12=27，14块锚点绝对值≤378、节点≤390。因此可用保守搜索盒做离线对照，但不变成玩法边界；远处用户布局按真实坐标验证，不按此盒拒绝。紧界或去旋转对称须另证，非本票必需。

## 独立验证顺序与复杂度

- 验池ID、数量、骨架、固定边和房型，不接受布局篡改块内部；旋转只用整数映射 `(x,y)→(-y,x)` 围绕锚点，坐标用足够宽整数并检查溢出。
- 从中心及半径0/1重建实际节点矩形；内部边必须骨架共边、使用该块间距；跨块边验不同块/Neow、轴向、最近边界恰留1格和端口。通路用从节点边界到另一边界的轴向线段表达，不能把图标中心段误判为穿自身节点。
- 对每对节点、节点与非关联边、每对边做整数矩形/线段相交检查。仅允许真正共享图节点的端点接触；同一直线重合拒绝。共端点不同方向合法，共端点同端口重用非法。3×3边角不能作连接端口。
- 验每对块跨边数、先古之民最多4边、Boss内部度/邻居链、内部四点连通和禁同类特殊房型邻接。近邻但未声明通路不建边。
- 手动提交先按声明通路找起点分量、以整块撤回无连接碎块，再验证剩余空间与图；自动候选直接校验，不借手动撤回悄悄修复搜索错误。
- 全图连通；删去所有Boss及其边后，所有保留普通点仍须从起点可达。再验证第一/第二Boss的准确邻居，避免仅“全图连通”放过Boss桥。
- 无权BFS至单Boss或第一Boss，距离≤额度。BFS给出路线节点序列；沿此简单路依次首次进入能按时到达。反向看，每个新进入点必须接到已完成区域，至少需要一条这么长的起点到目标链，因此免费中转不推翻此存在性判定。

最多57节点；粗全对几何 O((V+E)^2)，图检查 O(V+E)，普通空间哈希可优化但非必要。合法空间中轴向端口限制使边数很小；验证器不能对恶意重复/海量边先做二次比较，应先按节点端口、ID及最大可能度拒绝。生成搜索的最坏情况指数级，不能因验证便宜声称求解也便宜。

## 关键步骤与状态

```text
BuildPool(seed, rules):
  reserve a legal witness fragment and its compatible room slots
  allocate remaining shapes, room quota and connected internal edges constructively
  replace eligible slots with act Boss(es); do not change node count
  verify pool; instantiate witness from final pool IDs; Validate(witness)
  return original pool and witness
Auto(originalPool, savedInput, budget):
  keep savedInput untouched; validate matching witness as best
  enumerate attachments in stable order with seeded tie-breaking
  after each bounded expansion: reject conflicts; evaluate complete Boss layouts
  retain only independently valid candidates; stop at deterministic node budget
  if best exists: publish it once; otherwise return failure and savedInput
Submit(userLayout):
  withdraw disconnected whole fragments
  Validate(remainder); preserve withdrawal on failure
```

所有循环都有有限候选/预算。正常生成不重骰全池；可选择有限候选改善视觉，但不得失去见证。既有旧池无可用见证时，搜索达到预算返回UNKNOWN，UI按既定失败规则处理；若完整枚举穷尽才返回UNSAT。损坏池/不兼容规则/验证器拒绝保底见证属输入或实现错误，回旧布局并报错，不能静默换池。

复现至少依赖：完整原池（ID、形状、房型、Boss身份、固定边、锚点）、规则与算法版本、幕/进阶、额度、RNG类型及初始状态、稳定候选排序、确定性扩展预算。只给种子不够；并行调度和墙钟超时不能决定可复现的最终候选。可另用墙钟作紧急取消，但回退已知见证，不把超时后得到的部分结果当确定结果。研究记录提交版本只是来源定位，不新增hash机制。

存档：已开始生成应保存这次输入与随机状态；读档重做同次操作，而非领新种子。成功图作为确定结果保存，恢复不再求解。失败返回原布局的语义不同于手动提交保留撤回结果。具体序列化/统一发布交集成票，不预选网络协议或增加正式发布流程。

## 证据等级与后续

“已证明有解”是明确构造及其前提的数学结论，最终实现仍需独立验证；“实验找到解”只说明该输入有一个有效见证；“预算内未找到”不能证明不存在。此次不编译正式Mod、不启动游戏、不运行第三方构建脚本。构造方案足以在逻辑上选择混合路线，性能和体验数值不能由源码阅读推断。

后续最小原型须分离：数学/实现正确性（单/双Boss、七形状、配额、旋转、碰撞负例、恢复一致性），与体验/成本（14块池、15/14/13，成功布局碎块数/路线长度/多样性、扩展数与P50/P95耗时、预算命中率）。预算未知、过短Boss保底是否合意都须保留为验证问题；若体验要求新增最低路线长度或最低用块数，必须由用户确认后改变规则。实验票链接在本票resolution，不提前声称已完成原型。
