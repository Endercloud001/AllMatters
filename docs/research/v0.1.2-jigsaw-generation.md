# 自动拼图：有解池、布局求解与独立验证


**最新全局几何修订（2026-11-03，用户确认）**：所有节点实际占地之间至少留一格，适用于手动、自动、同块、异块、有边和无边节点，也检查对角靠近。普通节点半径 r=0，先古之民/Boss 的 3×3 占地半径 r=1。对任意两节点 a,b，要求 `max(|dx|,|dy|) >= ra+rb+2`；等价于实际占地在至少一个坐标轴方向有至少一整格间隔。轴向普通—普通中心至少2格、普通—大节点至少3格、大—大至少4格。不是要求所有节点中心统一距2格，也不要求边缘留2格；跨块通路仍恰好穿一格留白。节点与通路、通路之间的原碰撞限制继续单独执行。

## 将五个问题分开

1. **造池**：先选合法的骨架/内部边/Boss位置与房型赋值，再补齐库存；形状数量、房型配额、Boss替换前后统计分别检查。不以随机尝试最终成功代替保证。
2. **保证池有解**：池在交付前必须附带一份用本池节点ID构成、同时满足自动满额度探索要求的布局见证；独立验证通过才接受。见证是普通布局数据，不新增hash、contract或gate。不要求所有池节点都摆出。
3. **给池自动摆图**：先取满足满额度探索要求的有效见证作保底，再以有限预算回溯增加/替换碎块、换朝向、选择跨块边，择一个验证通过的候选。只能移动/选择原池块，不能重骰内部边/房型。任意外来池无合格见证时可求解，但预算耗尽不能报无解，也不能回退到只有短路线的旧见证。
4. **验任意布局**：不信任生成器的推导；从池与布局重建空间、通路、图和Boss结构，最后才运行限步BFS。
5. **失败与恢复**：成功候选在临时数据里构造并校验，统一接受后才替换旧布局。预算、取消、异常均有确定出口，正常路径绝不无限重抽。

## 无界地图的有限搜索

固定起点消除平移自由度。任何提交布局的碎块图连通，每个新块可沿一棵碎块生成树接入已有集合；因此可以穷举“剩余块×四旋转×已有普通点/起点×新块非Boss点×四方向”求唯一平移，使占地间恰留1格。这里只枚举接入所需边，其他可选边随后枚举；不要求玩家编辑也按连通顺序。

完整搜索需回溯生成树接入顺序与候选边，而不能贪心固定第一条接入边；允许停止在任意含Boss合法子集。所有形状旋转和节点数有限，至多14次接入，故此枚举有限。包含环的合法布局也有生成树，不因增量顺序漏掉；额外边不影响已有空间合法性，最后添加并检查配额。固定原点下每次跨边中心距至多3（Boss无跨边），块内锚点到任一点曼哈顿距至多3×4=12；粗界每次锚点增量≤12+3+12=27，14块锚点绝对值≤378、节点≤390。因此可用保守搜索盒做离线对照，但不变成玩法边界；远处用户布局按真实坐标验证，不按此盒拒绝。紧界或去旋转对称须另证，非本票必需。

## 独立验证顺序与复杂度

- 验池ID、数量、骨架、固定边和房型，不接受布局篡改块内部；旋转只用整数映射 `(x,y)→(-y,x)` 围绕锚点，坐标用足够宽整数并检查溢出。
- 从中心及半径0/1重建实际节点矩形；内部边必须骨架共边、使用该块间距；跨块边验不同块/Neow、轴向、最近边界恰留1格和端口。通路用从节点边界到另一边界的轴向线段表达，不能把图标中心段误判为穿自身节点。
- 对每对节点先检查全局一格留白 `max(|dx|,|dy|)>=ra+rb+2`，再对节点与非关联边、每对边做整数矩形/线段相交检查。仅允许真正共享图节点的端点接触；同一直线重合拒绝。共端点不同方向合法，共端点同端口重用非法。3×3边角不能作连接端口。
- 验每对块跨边数、先古之民最多4边、Boss内部度/邻居链、内部四点连通和禁同类特殊房型邻接。近邻但未声明通路不建边。
- 手动提交先按声明通路找起点分量、以整块撤回无连接碎块，再验证剩余空间与图；自动候选直接校验，不借手动撤回悄悄修复搜索错误。
- 全图连通；删去所有Boss及其边后，所有保留普通点仍须从起点可达。再验证第一/第二Boss的准确邻居，避免仅“全图连通”放过Boss桥。
- 无权BFS至单Boss或第一Boss，距离≤额度。BFS给出路线节点序列；沿此简单路依次首次进入能按时到达。反向看，每个新进入点必须接到已完成区域，至少需要一条这么长的起点到目标链，因此免费中转不推翻此存在性判定。
- **仅自动**：在上述全部检查通过后，要求保留布局中非 Boss 碎块节点数 N≥B−1，并构造满额度探索顺序作为证据；不对池内尚未放置的节点计数。手动提交不执行这个附加检查。

### 满额度探索的充要条件与线性见证

前提是几何及全部原合法性已通过，特别是删去所有 Boss 后，先古之民与所有保留非 Boss 节点连通，且单／双 Boss 终端正确。此时自动要求等价于 **N≥B−1 且起点到单／第一 Boss 最短距离 d≤B**。计数条件与 BFS 不能代替前置空间和拓扑验证。

必要性：B−1 次不同普通节点首次进入需要至少这么多节点；若能在第 B 步进入 Boss，已探索连通区域包含一条长度≤B的起点至 Boss 路径。

充分性：先取最短 Boss 路径上 Boss 之前的普通前缀，沿路径完成，普通节点数为 d−1≤B−1。保持 Boss 未进入，在删 Boss 的连通图中每次选择一个邻接已完成集合的未进入普通节点，直到完成 B−1 个；只要数量未满且 N 足够，连通性保证这样的边界节点存在。最后选择已经邻接已完成区域的单／第一 Boss，正好第 B 次进入。可按预先确定的节点和邻接顺序用队列维护边界，每个节点/边处理常数次，图检查与生成见证均为 O(V+E)。逐步模拟顺序检查目标未进入且邻接已完成区域；不要求上一目的地与下一目的地直接相邻。

因此不需求最长简单路径、Hamilton 路径或把最短距离强制拉到 B。Boss 可以直接邻近先古之民的分支，只要整张自动布局另有足够可合法探索的非 Boss 节点。额外节点需在实际保留布局中可达，不能用未放置池节点或重访凑数。

**新限制下的保底边界**：原“Boss I 在东、其他三块全在西”的四块构造不再满足直连邻块要求；任意四块也可能遗漏其他含休息处碎块，不能继续作为通用回退。可受控造池：将六个休息处分布于三个非 Boss 碎块的非相邻位置，并构造 Boss I 首普通点向上下分别连接另一个 I 和 O1，O1 再连 O2；实际坐标、配额兼容及验证见[构造笔记](v0.1.2-jigsaw-constructive.md)。这种受控池族与对任意既有池给出普适构造必须区分；给定其他池必须纳入它实际的全部含休息处碎块，不能重分房型迁就保底。旧满额度实验 [jigsaw_exact_budget_experiment.py](jigsaw_exact_budget_experiment.py)仅覆盖此前条件；新增受控构造实验 [jigsaw_rest_constraints_experiment.py](jigsaw_rest_constraints_experiment.py)另行记录，不将旧实验算作新规则验证。

### 必用碎块与 Boss 邻块验证

从原池求 R={含至少一个休息处的碎块 ID}，从实际布局求 U={已放置碎块 ID}，自动要求 R⊆U。从显式跨块边判断先古之民是否直接连接 Boss 碎块；若是，从同一边列表收集该 Boss 碎块直接相连、非先古且不同于自身的碎块 ID 集合 A，要求 |A|≥2。不以空间邻近或经多块间接可达代替直接边。此检查与满额度条件 N≥B−1、d≤B 分别执行：原充要定理仍只判满额度走法，不是所有自动新规则的充要条件。

造池及见证必须从一开始满足上述约束。给池搜索中，未放置必用碎块不能作为完成状态；直连 Boss 块且邻块不足两块时优先保留普通节点可用端口，只有可证明剩余碎块/端口不可能补足时才能剪掉分支。未能满足的候选不能因预算耗尽而发布；无已验证合格见证时按既定失败语义保留原图、原池与通路，不能换池、删休息处或关闭新检查。

最多57节点；粗全对几何 O((V+E)^2)，图检查 O(V+E)，普通空间哈希可优化但非必要。合法空间中轴向端口限制使边数很小；验证器不能对恶意重复/海量边先做二次比较，应先按节点端口、ID及最大可能度拒绝。生成搜索的最坏情况指数级，不能因验证便宜声称求解也便宜。

## 关键步骤与状态

```text
BuildPool(seed, rules):
  reserve a full-budget exploration witness layout and compatible room slots
  allocate remaining shapes, room quota and connected internal edges constructively
  replace eligible slots with act Boss(es); do not change node count
  verify pool; instantiate witness from final pool IDs; ValidateAuto(witness, B)
  return original pool and witness
Auto(originalPool, savedInput, budget):
  keep savedInput untouched; ValidateAuto(matching witness, B) as best
  enumerate attachments in stable order with seeded tie-breaking
  after each bounded expansion: reject conflicts; evaluate complete Boss layouts
  retain only ValidateAuto-passing candidates; stop at deterministic node budget
  if best exists: publish it once; otherwise return failure and savedInput
Submit(userLayout):
  withdraw disconnected whole fragments
  ValidateManual(remainder); preserve withdrawal on failure
```

所有循环都有有限候选/预算。正常生成不重骰全池；可选择有限候选改善视觉，但不得失去见证。既有旧池无可用见证时，搜索达到预算返回UNKNOWN，UI按既定失败规则处理；若完整枚举穷尽才返回UNSAT。损坏池/不兼容规则/验证器拒绝保底见证属输入或实现错误，回旧布局并报错，不能静默换池。

复现至少依赖：完整原池（ID、形状、房型、Boss身份、固定边、锚点）、规则与算法版本、幕/进阶、额度、RNG类型及初始状态、稳定候选排序、确定性扩展预算。只给种子不够；并行调度和墙钟超时不能决定可复现的最终候选。可另用墙钟作紧急取消，但回退已知见证，不把超时后得到的部分结果当确定结果。研究记录提交版本只是来源定位，不新增hash机制。

存档：已开始生成应保存这次输入与随机状态；读档重做同次操作，而非领新种子。成功图作为确定结果保存，恢复不再求解。失败返回原布局的语义不同于手动提交保留撤回结果。具体序列化/统一发布交集成票，不预选网络协议或增加正式发布流程。

## 证据等级与后续

“已证明有解”是明确构造及其前提的数学结论，最终实现仍需独立验证；“实验找到解”只说明该输入有一个有效见证；“预算内未找到”不能证明不存在。此次不编译正式Mod、不启动游戏、不运行第三方构建脚本。构造方案足以在逻辑上选择混合路线，性能和体验数值不能由源码阅读推断。

后续最小原型[验证自动拼图构造见证、搜索预算与布局体验](https://github.com/Endercloud001/AllMatters/issues/69)须分离数学/实现正确性（单/双Boss、七形状、配额、旋转、碰撞负例、恢复一致性）与体验/成本（14块池、15/14/13，非 Boss 可探索节点数、满额度探索顺序、房型分布、多样性、扩展数与P50/P95耗时、预算命中率）。单块 Boss 图必须在自动验证失败、手动验证通过；短 Boss 路径配足可达支路可自动通过，防止误加最短路下限。满额度探索已是用户批准的硬要求，不再询问是否接受三四步单块保底；不提前声称完整原型已完成。

## 演示页与全局留白验证

示例装配器的候选放置与最终独立几何检查均执行全节点对留白；普通点当前32像素/格、背景圆直径48像素，中心至少两格可避免旧一格相邻时的圆圈重叠。大节点标签单独避让邻近图标，不把标签尺寸反推成额外玩法占地。浏览器中同池随机装配仍满足全部休息处、条件Boss邻块和满额度要求；不恢复已删除的路线播放。新规则也必须由手动编辑落点检查、旋转检查、提交及恢复后的验证共同消费，不能只在自动采样器中实现。
