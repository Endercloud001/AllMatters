### 判定定理与证明

前提：原几何、Boss终端与连通规则已经通过验证。删去所有Boss后，先古之民及全部N个非Boss节点构成连通无权图H；单Boss只有一个普通邻居，双Boss的第一Boss只有一个普通邻居和第二Boss，第二Boss不连接其他节点。令d为原合法图先古之民到单／第一Boss的最短通路条数。

在这些前提下，新规则等价于 `N >= B-1 AND d <= B`。

必要性：合法走法已首次进入B−1个不同非Boss节点，故节点数足够。它们与起点始终形成连通的已完成集合，最后Boss邻接该集合。因此集合加Boss包含一条简单起点—Boss路径，其长度不超过B，所以d≤B。

充分性：先取一条最短起点—目标Boss路径，暂不进入Boss，依次完成其d−1个普通节点。它们与起点构成连通集合S，且包含Boss的普通邻居。若S中普通节点不足B−1，因H连通且总数N≥B−1，必存在尚未进入、邻接S的普通节点。任选一个首次进入并完成，加入S；反复进行至恰好B−1个。始终不进Boss，不重访商店。最后从已完成区域选择Boss，在第B次成功进入达到目标。不能用当前房间邻接代替已完成区域扩展，否则该证明不成立。

双Boss中第二Boss从H删除，不算B−1普通节点，也不能通过它中转；路径最短目标为第一Boss，其后的第二Boss按既有流程进入。上述证明不主张战斗必胜，只保证地图选择和计步层面的走法。

算法只需一次BFS、节点计数与按边界逐点扩展，O(V+E)。不是Hamilton路径问题：相邻两次首次进入节点可以通过任意已完成区域免费中转。独立验证空间/终端结构仍不可省略。

## 哪些骨架能放双Boss

双Boss终端要求四节点连通，剩余两个普通节点在删去Boss后仍连通。四节点内部必包含普通N1—普通N2—第一Boss—第二Boss的三边Hamilton路径。T骨架是K1,3，最长简单路径只有两边，故双Boss不能放T。I/S/Z/J/L本身是四点链，可在链末端放Boss；O可删去环上一条边形成链，因此可以放双Boss。单Boss则七种均可，但不能把唯一割点作为终端Boss；O尤其应选择并固定适当三边路径，而不是保留四边环令Boss度数为2。

最小枚举：2026-11-03，用Python标准库 itertools 在命令行枚举每形状所有骨架边子集、单Boss位置、双Boss有序位置；同时检查全图连通、删除Boss后的普通子图连通、单Boss度1，或第一Boss度2且邻接度1第二Boss。结果如下。数字是满足条件的“Boss位置+边子集”组合数，没有进行平移/旋转去重。

|I|2|2|
|O|8|8|
|T|3|0|

枚举是对上述图论推导的交叉核对，不是完整生成器验证；未验证所有空间嵌套和多人恢复，未编译或运行游戏，没有第三方构建执行。

以下为实际运行的枚举核心，使用Python标准库，可复制重现。输出即上表；不属于正式原型或生成器。

```python
import itertools
shapes = {
    'I': [(0,0),(1,0),(2,0),(3,0)],
    'O': [(0,0),(1,0),(0,1),(1,1)],
    'T': [(0,0),(1,0),(2,0),(1,1)],
    'S': [(1,0),(2,0),(0,1),(1,1)],
    'Z': [(0,0),(1,0),(1,1),(2,1)],
    'J': [(0,0),(0,1),(1,1),(2,1)],
    'L': [(2,0),(0,1),(1,1),(2,1)],
}
def connected(vertices, edges):
    seen = {vertices[0]}
    while True:
        new = seen | {b for a,b in edges if a in seen} | {
            a for a,b in edges if b in seen}
        if new == seen:
            return len(seen) == len(vertices)
        seen = new
for name, points in shapes.items():
    edges = [(a,b) for a,b in itertools.combinations(range(4),2)
             if sum(abs(points[a][j]-points[b][j]) for j in (0,1)) == 1]
    totals = []
    for boss_count in (1,2):
        count = 0
        for bosses in itertools.permutations(range(4), boss_count):
            ordinary = [v for v in range(4) if v not in bosses]
            for mask in range(1 << len(edges)):
                selected = [e for i,e in enumerate(edges) if mask >> i & 1]
                degree = lambda v: sum(v in e for e in selected)
                if not connected(list(range(4)), selected):
                    continue
                normal_edges = [e for e in selected if all(v in ordinary for v in e)]
                if not connected(ordinary, normal_edges):
                    continue
                if boss_count == 1 and degree(bosses[0]) == 1:
                    count += 1
                if (boss_count == 2 and degree(bosses[0]) == 2
                        and degree(bosses[1]) == 1
                        and tuple(sorted(bosses)) in selected):
                    count += 1
        totals.append(count)
    print(name, totals)
```

## 最新自动约束：必须用休息碎块与Boss块条件邻接

本节记录用户直接批准的两项自动专用规则，覆盖前文仅按B额度推荐旧见证的表述。它们不作用于手动提交；取消页面中的演示播放不删除游戏中的满额度探索要求。

定义原池块集合P，`R={p∈P | p含至少一个休息处节点}`，自动布局使用集合U，Boss所在块q。定义`neowLinked(q)`为先古之民与q中某个非Boss节点有已声明直接跨块通路；定义`neighbors(q)`为与q有已声明直接跨块通路的其他碎块ID集合，排除先古，按不同碎块去重。新验证为：`R⊆U`，以及`!neowLinked(q) || |neighbors(q)|>=2`。两条边连同一块只算一个邻居；经其他块间接到达不算直接邻接；靠近未连边不算。外边仍接q内普通节点，不能为了补邻居给Boss节点增加边。每对碎块最多两边等既有规则继续检查。

完整自动验收是旧空间/图/Boss规则、以上两式及满额度条件的合取。N≥B−1且d≤B的充要定理仍然只对“存在恰第B步进入Boss的探索顺序”成立，不能推导R⊆U或Boss块有两个邻居。旧四块坐标见证中Boss I只接先古，没有其他碎块邻居，因此明确违反第二项；而原配额分配可能把休息处放在未使用十块，亦可能违反第一项。历史实验18,077图用例与六个坐标用例只验证当时条件，不是新规则通过证据。

### 受控构造候选与当前证明边界

仍可研究受控池族：保留Boss I，另使用普通I、O1、O2，把六个休息处分成每块两个，放在这三块各自内部不相连的位置；池其他十块不放休息。Boss I通过普通节点直接接其中至少两块，普通区保持连通，且有足够普通节点。这样有望同时满足必须用全部休息块、条件邻接及满额度。该分布是算法候选的采样偏置，不新增“每块至多两个休息处”等玩法限制，不能套到任意已有随机池。

一个已由本次最小实验验证的受控构造：Boss I沿用历史向东坐标，普通I中心改为(3,2),(3,4),(3,6),(3,8)，O1为(3,-2),(5,-2),(3,-4),(5,-4)，O2为(7,-2),(9,-2),(7,-4),(9,-4)。外边为先古—Boss I首普通点(3,0)，该首普通点—普通I(3,2)，该首普通点—O1(3,-2)，O1(5,-2)—O2(7,-2)。Boss I直接邻居为普通I和O1，不把O2或先古充作第二邻居。普通I链隔一个位置放两个休息，两个O各放对角两个休息；内部链/环均不连接这对休息。Boss节点不承接外边。其余商店4、宝箱4可在未用十块的骨架独立集中分配，容量至少20≥8；Boss I预留四个普通战斗，剩余普通战斗/问号/精英按配额填满再替换Boss。该受控构造已通过下述新增最小实验，证明这一池族有符合新规则的保底；仍未给出任意既有池的普适证明，不覆盖旧实验标签，也不将示例当正式生成器。

更一般构造可先选择含全部R的连通见证，再补不含休息的余池，或先把R作为mandatory块联合求解。必须在发池前完成完整见证验证，证明的是该池而非所有可能房型分配。若改变受控池族以拓展形状/房型分布，应重新验证Boss端口、不同间距、空间交叉、固定内边与配额共同可满足；不靠隐藏重骰休息位置迎合布局。

### 有限搜索、剪枝与失败

有限搜索仍成立：最多14块、有限四旋转、端口接入唯一平移、可回溯接入次序；mandatory约束不引入无界坐标。沿用原有几何有限域证明即可。预计算R、每块房型和Boss身份；搜索状态记录已用U和Boss块不同邻居集合。终止输出时先检查R⊆U，不能沿用“只要有Boss且限步就提前成功”。所有mandatory块未加入前可以继续搜索，不能因当前未连通就过早判无解。

预算内按mandatory块的剩余合法候选数选择最紧变量、用空间碰撞/端口占用前向检查。若某个未用mandatory块在当前不可回退固定决定下所有候选均排除，该分支可剪；若剩余可用节点数量连同全部可能加入块仍不足B−1，也可剪。已直接连先古的Boss块若当前仅零/一个其他邻居，不立即剪枝；只有证明所有剩余合法候选最多不能再增加足够不同邻居，才可剪。Boss块尚未连接先古时不能提前强制两个邻居；该条件可以通过合法地不直连先古而不触发，不能偷偷升级为无条件最小度数。用过窄启发式窗口得出的零候选不是全域无解证据。

搜索/造池不得移动休息房型、删除固定内边、把两边同块当两邻居来掩盖失败。旧见证失效时不得继续作为成功回退；必须先有符合全部新条件的同池见证，或明确返回未找到/验证失败。自动搜索在工作副本执行，失败保留原池、原布局、原通路，清票与错误反馈沿既定多人规则；不擅自重发池或把恢复的旧池宣称有解。完整有限搜索穷尽才是该输入不可解证明；预算耗尽仍为未知。

### 新增最小验证问题

需扩展独立验证器及最小几何实验后才可重新宣称四块候选可作保底：逐个检查六个rest所在块全部使用；缺任一休息块拒绝；Boss块直连先古但只有一个其他块拒绝；连同一其他块两边仍拒绝；两个不同邻居通过；不直连先古时不强制两邻居；Boss本身外边继续拒绝。单/双Boss与B=15/14/13都需重复完整几何及满额度验证。任意原池的受限/无解反例与预算失败亦须记录。以下已运行实验只覆盖指定受控构造；上列全部负例与任意池的搜索验证仍由原型补齐，不实现正式生成器。

### 本次新增实验结果

主代理独立重跑 [jigsaw_rest_constraints_experiment.py](jigsaw_rest_constraints_experiment.py)，退出0：完整14块56节点配额20/16/6/4/6/4准确，6休息处分布三块且全部使用；单/双Boss各四个整体旋转（8布局）通过占地、轴向通路、无交叉重合、端口、跨块上限及Boss终端检查。每例对B=15/14/13逐步验证首次进入探索顺序，共24额度用例。Boss块直接连接先古及两个不同其他块；单N=15,d=4，双N=14,d=3。旋转是整个构造的四个方向，非单块任意转动后原外边仍成立。该证据是受控池族构造可行，不是随机既有池总能补齐的证明。

本机交互页面使用原先休息处分散的固定池（5块含6休息），按新增mandatory与条件邻块规则有限随机装配；三模式各100种子共300样例通过页面验证，休息处6/6，触发条件时不同Boss邻块至少2。此为演示样例证据，未运行游戏或正式生成器。页面取消路线播放，但仍验证满额度条件。

### 全局留白修订后的构造验证

新增全节点对留白检查后，旧休息处构造的双Boss E2 与 O2/C1 在对角方向不够一整格，实际触发失败（不是仅显示问题）。已将 O2 改为 `(5,-6),(7,-6),(5,-8),(7,-8)`，外边由 O1 `(5,-4)` 接 O2 `(5,-6)`；其余坐标、房型与Boss结构不变。原段落保留历史，涉及 O2 旧坐标和旧外边时以本节及当前实验脚本为准。

独立重跑两实验：新休息构造的单/双Boss×四整体方向共8布局、24个额度用例通过全局留白及原有全部检查；旧满额度实验18,077图对照继续通过，指定坐标见证亦加上全节点留白检查。演示页另在三个模式各100种子共300布局检查全部节点对及绘制背景圆，间距规则适用于未连线和对角靠近，不能只查跨块通路端点。受控池证明范围不变，不据此承诺任意原池都有解。
