## 结论：当前规则允许极小的确定性见证

由于不要求用完池、不要求最少房间或最短路线长度，预留一块 I 形 Boss 碎块即可构成合法提交。这里的“有解”具有显式坐标见证，不依赖随机重试。

单Boss：先古之民中心(0,0)，I形四点依次为普通A(3,0)、普通B(6,0)、普通C(9,0)、Boss(12,0)。内部边为A—B—C—Boss，外部仅先古之民—A。先古之民占[-1,1]×[-1,1]，到A之间空格是(2,0)；Boss占[11,13]×[-1,1]，C到Boss的空格为(10,0)。内部节点统一间距3，四条通路共线但区间互不重合，只有合法共同端点。删除Boss后所有普通节点仍可从先古之民到达。路线长度4≤13≤14≤15。

双Boss：同样用 I，普通A(3,0)、普通B(7,0)、第一Boss(11,0)、第二Boss(15,0)。内部A—B—第一Boss—第二Boss，外部先古之民—A。统一间距4；两Boss占地间正好一格，第一Boss只连B和第二Boss，第二Boss只连第一Boss。到第一Boss长度3≤13，其后第二Boss不参与限步终点判断。所有边端口方向唯一，不存在穿Boss访问普通节点。

其余13块留在池中。这不是删除池内碎块，也不违反14块56节点；只是见证布局仅放置其中一块。可整体绕先古之民旋转四种方向，固定锚点选择I端点，旋转与整数吸附均可表达上述坐标。

这说明现行规则并无“15/14/13可能根本无法实现”的逻辑矛盾，却不说明三四步Boss图有良好体验。不能据此擅自新增最少用块、最短路线或必经商店等玩法；若不接受此类自动结果，应交用户与体验原型决定。把它作为数学见证或技术回退，与把它作为玩家日常自动输出，是不同层面的选择。

## 配额分配也能有限完成

1. 创建I/O/T/S/Z/J/L各两块的骨架，预留其中一块I为Boss载体；先确定当前普通房型配额。
2. 把预留I的四个位置分配为普通战斗。此时还未做Boss替换，满足先普通分配、后替换的顺序。
3. 每个其他骨架按局部坐标(x+y) mod 2二分，选择至少含两节点的一侧，并从该侧取恰好两点，得到13×2=26个互不骨架邻接的可选特殊位置。商店4+休息6+宝箱4共14个，因此有足够容量。随机取14个位置再按三种配额分配，任何内部骨架边都不可能连接两个特殊位置，故尤其不会出现同类特殊房间相邻。
4. 剩余38个位置按普通战斗16、问号16、精英6分配。加上预留I四个战斗，替换前配额精确为20/16/6/4/6/4。可以约束洗牌，不是事后改配额。
5. 普通碎块内部从骨架共边选任意生成树，或加回任意骨架边；有限的四节点边子集可枚举。预留I使用三边链。随后按幕模式将I末端一个战斗替换为单Boss，或链末端两个相邻战斗替换为第一/第二Boss，再按3或4统一缩放I。
6. 将上述合法见证与实际池一起交给独立验证器。配额从替换前类型数据核对；替换后的普通战斗数量应是19或18，不能误补回20而使56超额。

普通图中14个特殊节点放在独立集中是充分条件而非玩法限制：正式随机化可以在预算内使用更宽松且仍合法的分配，也可让不同特殊类型相邻。退路只需这个受限子集。构造不会均匀采样全部合法池，应明示这一随机分布偏差；均匀性不是当前硬规则。

复杂度：固定56节点的配额分配与骨架建图O(56)，每块最多4条骨架边，内部图枚举最多16子集，池构造无不定次数重试。见证只需4个碎块节点与先古之民，独立验证成本有确定上界。有限库与构造在实现前需要检查坐标、类型及端口，但数学存在性无需运行正式求解器。

## 哪些骨架能放双Boss

双Boss终端要求四节点连通，剩余两个普通节点在删去Boss后仍连通。四节点内部必包含普通N1—普通N2—第一Boss—第二Boss的三边Hamilton路径。T骨架是K1,3，最长简单路径只有两边，故双Boss不能放T。I/S/Z/J/L本身是四点链，可在链末端放Boss；O可删去环上一条边形成链，因此可以放双Boss。单Boss则七种均可，但不能把唯一割点作为终端Boss；O尤其应选择并固定适当三边路径，而不是保留四边环令Boss度数为2。

最小枚举：2026-11-03，用Python标准库 itertools 在命令行枚举每形状所有骨架边子集、单Boss位置、双Boss有序位置；同时检查全图连通、删除Boss后的普通子图连通、单Boss度1，或第一Boss度2且邻接度1第二Boss。结果如下。数字是满足条件的“Boss位置+边子集”组合数，没有进行平移/旋转去重。

|骨架|单Boss|双Boss|
|---|---:|---:|
|I|2|2|
|O|8|8|
|T|3|0|
|S|2|2|
|Z|2|2|
|J|2|2|
|L|2|2|

枚举是对上述图论推导的交叉核对，不是完整生成器验证；未验证所有空间嵌套和多人恢复，未编译或运行游戏，没有第三方构建执行。

以下为实际运行的枚举核心，使用Python标准库，可复制重现。输出即上表；不属于正式原型或生成器。

```python
import itertools
shapes = {
    'I': [(0,0),(1,0),(2,0),(3,0)],
    'O': [(0,0),(1,0),(0,1),(1,1)],
    'T': [(0,0),(1,0),(2,0),(1,1)],
    'S': [(1,0),(2,0),(0,1),(1,1)],
    'Z': [(0,0),(1,0),(1,1),(2,1)],
    'J': [(0,0),(0,1),(1,1),(2,1)],
    'L': [(2,0),(0,1),(1,1),(2,1)],
}
def connected(vertices, edges):
    seen = {vertices[0]}
    while True:
        new = seen | {b for a,b in edges if a in seen} | {
            a for a,b in edges if b in seen}
        if new == seen:
            return len(seen) == len(vertices)
        seen = new
for name, points in shapes.items():
    edges = [(a,b) for a,b in itertools.combinations(range(4),2)
             if sum(abs(points[a][j]-points[b][j]) for j in (0,1)) == 1]
    totals = []
    for boss_count in (1,2):
        count = 0
        for bosses in itertools.permutations(range(4), boss_count):
            ordinary = [v for v in range(4) if v not in bosses]
            for mask in range(1 << len(edges)):
                selected = [e for i,e in enumerate(edges) if mask >> i & 1]
                degree = lambda v: sum(v in e for e in selected)
                if not connected(list(range(4)), selected):
                    continue
                normal_edges = [e for e in selected if all(v in ordinary for v in e)]
                if not connected(ordinary, normal_edges):
                    continue
                if boss_count == 1 and degree(bosses[0]) == 1:
                    count += 1
                if (boss_count == 2 and degree(bosses[0]) == 2
                        and degree(bosses[1]) == 1
                        and tuple(sorted(bosses)) in selected):
                    count += 1
        totals.append(count)
    print(name, totals)
```

## 推荐给主研究的边界

先构造一个经过验证的池与见证，再对同一池在有限预算内搜更丰富布局；每次候选独立验证，失败仍有原见证。构造只是保证存在，后续丰富化不应改固定内部边或房型以迎合求解。自动运行成功后才替换用户编辑布局，失败保留原布局与原池，遵守多人票；不能因搜索超时擅自重抽池。

可明确表述的后续实验：在固定池下，预算内追加/重排能用多少碎块、最短路分布及空间大小如何；单/双Boss，额度15/14/13，至少数百种固定种子，测成功率、展开数、耗时分位、可用块数、路线长度、失败原因。见证有效性失败一次即构造错误；预算耗尽只表示未找到更优布局，不能称池无解。体验是否接受极短回退地图必须由用户判断，不由算法证明代替。
