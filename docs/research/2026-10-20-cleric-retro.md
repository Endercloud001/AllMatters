## 改进候选（按影响排序）

1. **工作区与本机依赖的连续性。** 切换到 main 时，Git 状态和未跟踪文档虽恢复一致，但 docs junction 被替换为普通目录，导致 `docs/local` 下的日志和 RitsuLib 无法访问。这说明只看 `git status` 不足以验证本机工作区。原数据仍在相邻 AllMatters_docs，本轮已保存当前普通目录副本、同步文档并恢复 junction；31 份文档逐字节比较一致，原有 Git 改动也未改变。建议日后从源头将本机依赖与 Git 管理的文档目录解耦；在此之前，涉及切换/暂存时检查 junction 与已配置依赖路径。这里只是具体环境恢复，不增加 hash、冻结文件或 gate。

2. **测试结论必须对应实际产物。** public 失败时曾尝试给待打出的牌预先入手牌，普通单项表面通过，混合测试却显示结果仍是两张原 Hello World，属于错误的修复方向。最终撤销临时改动，仅提前现有宿主替代的安装顺序，两目标各 20/20 通过。现有测试已经捕捉这个错误，不需要再造一套测试框架；宿主调整应复用这组行为回归，不能为了单项通过降低断言或移开真实失败入口。初始化入口已补到 development.md。

3. **PR 范围与审查范围应对齐。** #3 的双向审查只覆盖 265e961 之后的实现；PR #16 实际还携带此前未合并的六个准备提交。PR 已如实说明这些改动，但本轮的 #3 审查不能当成全部九个提交均已重新审查。建议后续开始工单时核对相对 main 的提交清单；出现额外提交时选择独立分支，或在合并前补审扩大的差异。跨提交需求关联属于 reviewer 的判断，不适合用文件名黑名单替代。

4. **验收边界应一次写准。** 曾将完整 public、真实联机及回放等未验证项一并写成 #3 不能关闭的条件，超出了该票明确留给集成票的边界，之后才修正。建议验证记录直接引用本票 acceptance criteria，把本票完成证据和后续集成证据分开；用户的整体实测确认不扩写为每一细项已单独实测。现已在 development.md 明确这一原则。

5. **已有检查没有自动入口。** 已核对 Build.ps1、Test.ps1、项目文件和 Git 配置：项目有双目标构建及真实程序集行为检查，但没有 CI workflow、有效 pre-commit/pre-push hook 或自定义 hooksPath。候选是复用现有命令设置可运行的本地自动检查，而非编写 reviewer 提醒去代替机械检查。完整测试依赖本机游戏 DLL、Godot、RitsuLib 和资源，不能直接搬到公共 runner，更不能上传这些开发输入。遵循用户“不默认新增 gate”的约束，本轮未新增 hook、CI 或阻塞规则。

6. **减少工具重试和大输出。** GitHub fetch_pr 的结果含完整 diff，本轮曾输出约 6 万 token；后续应先取结构化状态、只返回 number/state/head/mergeable，必要时按文件取 patch。CLI 多次 TLS/连接失败后才查出 Windows 已配置系统代理，而 Git 未使用它；应更早检查现有网络配置，读写 GitHub 元数据可复用已连接工具。Git 传输只对当前命令使用既有系统代理，不改全局配置、不输出凭据。API 查询已经支持 -Find/-Signatures/-Member/-Limit，应继续先摘要再按需读方法体。
