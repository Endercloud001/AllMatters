# v0.1 实施顺序

1. 准备 public 对应的真实程序集，比较 public/public-beta 的事件、模型注册、卡牌、能力、命令与战后流程 API。评估可同时支持两分支的 RitsuLib 版本；如有差异，选择小范围适配或分别构建，记录原因。**2026-10-20 已完成开发资料准备与编译验证**：从 GitHub 获取并核对 public 0.107.1 实际 DLL，准备两版引用程序集，与本机 beta 0.111.0 对比；选择 RitsuLib 0.6.7 和分别构建方案，下载完整运行包，并完成双目标骨架与框架接入点编译。见 [API 比较、来源及验证边界](research/dual-branch-api.md)、[RitsuLib 调查](research/ritsulib-compatibility.md)。真实游戏加载与玩法验收仍待进行；public 尚无本地完整游戏环境。
2. 实现你好世界升级调整；针对升级状态、生成实例和原版池语义验证两分支行为。
3. 引入事件注册和公共事件/遗物支持；从牧师、老乞丐、神圣泉水、大图书馆开始，打通中文、英文、本地化与事件图片的 Godot PCK 导出。
4. 移植增益研究者、诅咒书本、大转盘、红面具大人之墓及其遗物、J.A.X.、死灵诅咒和能力。先处理 scope 文档里列出的手册冲突。
5. 移植面具强盗、竞技场、心灵绽放的遭遇、怪物、相关能力、奖励与战后恢复链。此阶段必须检查多人和中途保存恢复。
6. 每批只针对具体风险增加普通测试；完成两分支真实加载与玩法回归，核对授权、来源及安装说明，再准备 v0.1 发布包。

任务使用 GitHub Issues；初始化提交包含代码骨架、构建脚本与开发资料，尚无玩法实现或正式发布。各阶段结果和未验证项写回文档。
