# AllMatters v0.1：一代事件回归开发规格

日期：2026-10-20。玩法依据：已确认的事件表与 Q1–Q20；Grill 已结束。测试入口已由用户于同日确认。本文是功能规格，不表示事件已实现或验收通过；GitHub 发布信息由实施计划记录。

## Problem Statement

玩家希望在《杀戮尖塔2》中体验经过指定调整的 11 个一代经典事件。直接复制 Balance 会带入不同的战斗、奖励、诅咒、遗物机制和出现条件；部分事件还存在不可达选项、两版本内部流程不同及多人重复结算风险。现有 AllMatters 仅实现你好世界调整，尚无这批事件、独立资源包或生产环境中的 RitsuLib 接入。

开发需要一份可在后续会话中独立使用的规格，保留已确认玩法，并将模型测试、实际加载、完整战斗恢复、联机、存档和回放各自能够证明的结果分开记录。

## Solution

交付且仅交付以下 11 个事件及其必要卡牌、能力、遗物、遭遇和资源：老乞丐、诅咒书本、蒙面强盗、增益研究者、神圣泉水、牧师、心灵绽放、变化大转盘、红面具大人之墓、大图书馆、竞技场。

需求冲突时以《v0.1 范围》的事件表为准，其次为已确认补充规则。未被修改的行为沿用 Balance，而非自动还原一代。本文将当前已确认内容整理成可验收行为；后续变更需同步范围与规格，不能用上游默认值覆盖明确改动。

支持此次核实的 public 0.107.1 与 public-beta 0.111.0，采用同一业务源码、分别构建对应目标。提供中英文文案和实际可加载的图片、怪物及其他必需资源，支持个人选择、共享选择、共同战斗奖励和原生保存恢复。

## User Stories

1. 作为一名玩家，我希望只增加指定的 11 个事件及必要依赖，以便体验本轮玩法而不引入整套 Balance 调整。
2. 作为一名玩家，我希望幕、层数、金币、牌组和遗物条件实际控制事件出现，以便不会遇到条件不符的事件。
3. 作为一名玩家，我希望无法支付费用或没有合法选牌目标的主动选项被禁用，以便不会支付后得到无法完成的效果。
4. 作为一名联机玩家，我希望个人选项只由选择者承担费用和获得效果，以便独立选择不会改变队友的个人资源。

## Implementation Decisions

### 1. 范围、继承与出现条件

- 首要依据为已确认事件表；未修改部分沿用 Balance，包括尼利宝典候选升级、J.A.X. 除固有以外的基础效果、未被替换的强盗奖励和相关遗物/怪物机制。上游后来变化不自动变成本规格的新需求。
- 下表中的层数是本局累计层数；Act 2/3 分别为第二/三幕。无额外幕条件的事件不擅自增加条件；“全员”表示事件准入时逐名玩家检查。
- 个人事件：老乞丐、诅咒书本、增益研究者、神圣泉水、牧师、转盘、墓穴、图书馆。共享选择事件沿用 Balance：蒙面强盗、心灵绽放、竞技场。注册到共享事件池不等于共享决策。
- 不通过提高事件门槛处理无法执行的主动选项。金币不足、没有可选牌或原初始遗物不再持有时禁用对应选项；书本可能致死属于明确例外，不按生命余额预先禁用。

### 2. 诅咒书本、书籍与致死流程

- 初页阅读不扣血，也可离开。阅读后依次失去 1、2、3 生命；三个中间页面只有继续，不新增退出。末页拿走额外失去 15，所有进阶相同，名义累计 21；停止额外失去 3，名义累计 9。
- 拿走先完成伤害及防死亡/复活处理，仍存活才主动选择死灵之书、尼利的宝典、英雄宝典中的一本；不是随机奖励，也不连续领取多本。每名玩家独立选择，可以选择与队友相同的书。
- 允许致死选项，呈现原生致死提示。每次伤害后，确认死亡即结束该玩家事件且不发书；不因一个人的死亡中断存活队友的独立选择。名义损血不是绕过原生伤害、减免、防死亡或复活的手动扣生命。
- 三书效果沿用 Balance：死灵之书附加死灵诅咒，并额外打出每回合首次符合已解析能量费用至少 2 的攻击；尼利宝典在回合结束提供三张本职业候选，候选升级，允许按上游流程选择后洗入抽牌堆；英雄宝典在每场战斗第一回合生成一张合法本职业能力牌，本回合免费。相关过滤、随机和堆满处理保持原生命令/上游未修改语义。
- 原版一代末页通常为 10、A15 起为 15；本规格明确统一 15，不映射两代进阶编号。Wiki 页面读取失败不再构成规则阻塞，已有本机一代原版的一手流程证据。

### 3. J.A.X.、突变之力与绽放印记

- J.A.X. 为 0 费技能，默认固有，失去 3 生命并获得 2 力量，升级后为 3 力量；除默认固有外按 Balance。固有必须实际影响未升级实例，而非只改描述。
- 变化后升级作用于所得新实例，不升级已被替换的旧牌或修改共享模板。
- 使用角色原初始遗物定义识别交换目标，不按遗物栏位置猜测。五个目标原版角色均只有一件初始遗物；缺失或被替换时禁用喝突变剂，不免费获得突变之力。
- 突变之力每场开战获得 3 力量；前两个拥有者回合结束不扣，第三个拥有者回合结束一次失去 3。保持 Balance 衰退 Debuff 与人工制品等未修改交互，不改成每回合失去 1，也不因其他玩家回合提前扣除。
- 绽放印记阻止持有者回复生命；不影响其他玩家。战斗治疗、休息、事件治疗及恢复相关原生效果应沿已确认治疗钩子接入，不能只改某一种治疗调用。
- 原生诅咒对应为：凡庸 Normality、贪婪 Greed、执迷 Enthralled、悔恨 Regret、霉运 BadLuck。执迷不是 Writhe（苦恼）；永久关键词与可移除限制保持目标版本行为。

### 4. 大图书馆与瓶装绑定

- 跨职业卡牌只来自其他四个原版角色的合法奖励牌；按拥有者解锁状态和当前人数限制筛选。排除当前角色、无色、诅咒、事件专属与 Mod 角色牌。合并合法候选后逐牌随机、不放回抽样，最多 20 张，不先随机角色，也不以重复牌凑足数量。
- 合法候选为 1–19 张时展示全部，仍选一张加入牌组；零候选禁用阅读。阅读生成的升级等未修改规则沿用 Balance，不将 Boss 奖励策略误用于阅读。
- 打扫仅在“尚未持有且有合法绑定目标”的瓶子种类中等概率抽一件；没有任何可用瓶子则禁用打扫。
- 火焰对应攻击、闪电对应技能、旋风对应能力；目标必须没有固有且未被其他瓶子绑定。获得后必须绑定一张，不可取消。
- 瓶装绑定赋予指定牌固有。升级保持关联；持有遗物时禁止战斗外移除或变化绑定牌，但战斗内允许消耗/变化。
- 战斗内变化仅作用于当前战斗，产物不继承瓶装绑定；永久牌组原牌继续绑定，下一场仍由原牌获得固有。战斗内消耗同样不解除原牌绑定。
- 失去瓶子解除关联与瓶子赋予的固有，不移除该牌后来从其他来源获得的固有。保存恢复不能丢失关联或将其按牌名转移到另一张同名牌。
- 三瓶 v0.1 仅由图书馆打扫提供，不进入常规掉落、商店或其他事件通用随机遗物池。

### 5. 随机分布、空池与层数分支

- 转盘六种结果各 1/6；以同一次已确定结果驱动动画与结算。删牌无目标时依次显示抽中结果、说明无可移除牌、结束；不重抽、不补偿。
- 转盘遗物在普通、罕见均有合法候选时先各 50% 选档，再在该档合法候选中随机抽取。只有一档非空则抽该档，两档均空说明后结束；不重抽转盘、不引入其他稀有度或补偿。合法候选尊重对应原生领取条件与已确认瓶子排除规则。
- 心灵绽放 37 层及以前出现富有，38 层起出现无伤痛，单双人相同且互斥。富有获得 999 金币、凡庸与贪婪各一张；无伤痛回满生命、执迷与悔恨各一张。
- 墓穴不足 150 金币禁用献上敬意；已有红面具的玩家能正常选择 222 金币分支。原生遗物持有约束及其他未修改选项逻辑沿用 Balance，不重新注册红面具。

### 6. 事件战斗、共同战斗奖励与多人执行

- 心灵绽放仅一场双乐加维林战斗。使用 Balance 的一代乐加维林，不能替换为二代乐加维林族长；默认沉睡及进阶数值不另行强化。两只各自睡眠、计时、受伤唤醒；多人血量交给原生创建/缩放链，不能先自行加倍后再重复原生缩放。
- 竞技场首战完整组合为一只活雾、一只潮湿邪教徒；胜利不产生默认金币、卡牌、遗物或其他战利品，直接恢复中场选择。逃离无奖励；继续才进入第二战。
- 第二战仅在残杀千足虫、蜂群术士、感染棱柱三个完整原版第二幕精英遭遇中各 1/3 抽取，不受图鉴是否发现影响、不纳入 Boss 或 Mod 遭遇。保留完整组成、专用场景、行动、进阶、多人缩放及原生召唤行为，不能把千足虫裁成一节。
- 心灵绽放凯旋及竞技场第二战胜利，每位参战者各得 100 金币、一件随机稀有遗物和一次正常 Boss 规则的卡牌奖励；不叠加被替换的默认房间战利品。
- 卡牌奖励基础为本职业稀有牌三选一、可跳过，遵守原生解锁、人数、升级概率及奖励修改效果。保留原生修改候选、升级、数量及可多选等效果；不能为强制永远三选一而屏蔽这些钩子。基础稀有牌升级概率为 0，仍允许原生效果修改。
- 复用 Boss 卡牌生成策略，不把实际事件房间或精英遭遇改成 Boss，不触发正常过幕。
- 个人选择仅结算选择者；统一选择事件各玩家承担相应费用与获得效果。原生共享事件会执行各玩家自身实例，不能在每次回调里再遍历全队重复结算。
- 连续战斗分别维护房间恢复、回放初始化、奖励领取与既有事件状态。public 与 beta 内部恢复机制不同，不能照搬 beta 私有同步器到 public。

### 7. 加载、资源、保存与兼容

- 事件及模型注册、文字、事件图片、怪物场景及必要资源必须在同一实际可玩交付中工作。接入 RitsuLib 0.6.7 对应分支模块及完整运行包，正确声明依赖并生成实际 PCK，安装说明与产物一致。
- 使用 AllMatters 自身模型/资源身份，不复制整个上游运行时、不改变无关原生池，不分发游戏 DLL、原版 JAR 或反编译输出。
- 以原生可变模型、命令、玩家归属、同步随机源和既有保存恢复机制承载行为。保留费用已支付、随机已确定、奖励已领取和瓶装关联等真实状态，恢复不能重复副作用；不新增额外 hash、冻结 contract、baseline 或 gate。
- public 与 beta 分别构建，对实际不同的调用点局部适配。编译、模型行为、PCK 实际加载、完整游戏、联机及回放分别记录证据，不用一个结果替代另一个。
- 复制上游代码或素材前落实对应许可、归属和项目整体许可证；资源独立核对，不执行参考仓库的构建或部署脚本。保留既有你好世界行为与测试。

## Testing Decisions

### 已确认的测试入口与复用边界

用户已确认以“进入事件 → 选择选项 → 检查金币、生命、牌组、遗物、奖励及结束状态”为主要自动化测试入口。测试通过公开/受保护的真实模型与选项执行路径观察结果，不把私有字段布局、类拆分、调用次数或实现细节作为验收目标。

优先复用既有 Godot 无界面测试基础设施、真实目标程序集、模型工厂、命令、RNG 和本地化初始化。既有你好世界测试提供实例隔离、拥有者、人数/解锁筛选、升级、语言和随机状态的先例；其宿主替代了全局战斗进行中状态与空手通知，不能直接证明真实房间、网络、死亡结算或战斗恢复。

事件动作驱动及必要的选择回答能力可在上述最高行为入口补足，不为每个事件新增独立测试框架。计时和绑定跨战斗等无法仅用一次选项证明的行为，从真实回合/战斗命令驱动，并检查玩家实际结果。替代全局生命周期的场景必须注明替代边界。

测试围绕下面的具体失败场景设计；避免机械镜像实现或为低影响文案添加无意义测试。随机分支可通过可控的原生随机源/候选准备逐一触达，验证分布规则和不重抽语义，不用有限次数的频率采样代替概率分支检查，也不新增测试专用 hash 或基线。

### 版本与验证边界

- 自动化针对两版真实目标程序集分别执行，保留版本、命令、通过/失败及替代边界。现有你好世界每分支 15 项通过和 beta 用户验收仅是先例，不是这批事件的通过证据。
- 本机 beta 有完整游戏环境；public 当前仅有 DLL 与 API 参考。使用 beta 资源支撑的 public 无界面测试不能替代完整 public 加载、画面、玩法或联机验证。
- RitsuLib 接入探针只证明签名编译；现有生产包仍无事件 PCK 或框架依赖。首个纵向实现应同时贯通一个简单事件、必要依赖、语言、资源、构建与 beta 实际加载。
- 房间战斗恢复、网络同步、回放、死亡/复活和资源视觉必须分别取得相应实机证据；不能仅凭无界面宿主的替代生命周期宣称完成。
- 准备完整 public 环境不阻塞 beta 首票或 public 编译适配，但在宣称双分支实机兼容及正式发布前必须补齐对应验收。
