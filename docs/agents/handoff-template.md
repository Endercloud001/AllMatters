# Agent 交接模板

派发或交接时填写下列单屏入口，直接放进任务消息或现有卡片；按[批次流程](batch-flow.md#3-并发与角色最多两片在制按阶段换人)选择精简上下文。接手者先核对身份和现场，再执行下一动作；现场不符时把差异交回主控。

```text
角色/owner：实施、只读研究、审查轴或唯一执行者；目标卡/issue：链接到具体卡片/验收条目。
位置：绝对worktree；分支；起点提交SHA。
现场：staged / unstaged / untracked 分别列路径或“无”；区分本片与既有改动。
下一动作：一条可执行动作；触发 → 行为 → 可观察结果；依赖是否就绪。
权限：允许写的文件/符号；只读入口；可执行的命令/唯一执行权归属。
停止边界：结束条件；越界/失败交回谁；剩余验收归属（Not in Scope）。
依据：目标规格章节/用户决定、已核源码符号/API；只链接本片相关证据与准确位置。
验证/回交：最小命令和预期；已证的提交/范围、目标、日志及复用失效条件；未证项。
审查：git diff --cached <起点SHA> -- <本片路径>；回交实际状态/命令/结果及提交SHA（或未提交）。
```

## 按需证据

依据只给实际存在的链接、日志路径和必要行/章节/符号；大文件留在原处，按问题窄读。恢复/联网的expected来源、工具链委托与证据复用按[批次流程](batch-flow.md)对应章节补充，不复制整板或全部历史。

## Not in Scope

填写本片未承担的行为、原因、接收issue/owner和恢复条件；待人工验收逐条标明归属。局部验证完成只结束本片，主控继续调度并维护唯一集成树看板。

## 交付阶段

进入项目规定的集成/发布交付阶段时，按[开发入口](../development.md#实机验收交付)和[批次流程的验证范围](batch-flow.md#4-控制测试成本每次运行都回答问题)执行完整Check、审查通过后同提交双版包、验收文档和用户实机验收；普通片内交接只列本片所需验证。hooks与安全要求仍按仓库规则执行。
