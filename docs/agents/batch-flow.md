# 多 issue 切片、调度与验证

主控负责把已授权批次推进到验收边界。每片结束后更新看板、解开依赖并继续，不以“完成一轮试行”作为停工点。Git、安全、正式发布/安装和人工验收仍遵守仓库要求；本页不授权跳过hooks、清理旧树或关闭未完成工单。

## 1. 一张票怎样变成可派发的垂直片

先对照目标issue、父规格和当前实现，把验收条件分成已证、待实现、待补证、待人工。最新明确结论覆盖历史“待办”；按证据定位，不整篇重放旧主控记录。整票只做范围核对，下一步只细化最近要拉取的1–2片，避免为全部远期任务写会过期的文件级计划。

一片描述一个真实触发、一个行为差异和一个可观察结果，贯穿它必需的生产/测试/资源层。例如“受罚敌人自然开场得到规定能力，普通对照不变”，优于“先写所有patch，再写所有测试”。文件少、代码少不是切片完成标准；一份资源准备或API研究可作为使能任务，但不能冒称用户行为已交付。

拆分步骤：

1. 从一条未满足验收取出具体场景，写明输入、owner/人数、目标版本和期望变化。
2. 沿真实入口追到最小修改接缝及相邻消费者；记录实际文件路径、类/方法或测试case。Harmony目标必须用目标版本API核实。
3. 划清允许写入的文件/符号和共享热点。跨热点要先排所有权；预计文件只是初始边界，实施者发现新事实时向主控报“需要增加哪里、为什么”，由主控调整，不让错误路径指示锁死实现。
4. 选择能报目标错误的最小测试，以及会受此次改动影响的相邻回归。没有真实失败能力的mock不能替换原生恢复/顺序故障。
5. 写结束条件和剩余验收归属；若还包含互不依赖的第二个行为，拆开。若分开只留下无法验证的半条链，合并。一次编译错误、一个变量更名或每条断言不另建卡。

“最小”指可独立审查并验证的有用增量，不是每改几行就支付两次审查和一轮集成的成本。共用同一接缝、测试和验收的小改动可在同片完成；资源、合法状态或API尚不清楚时先做有具体问题/输出/停止条件的短研究，不先堆代码。

只增强效果、未新增怪物的片默认沿用原场景、贴图和坐标；帝皇蟹Artifact3沿用原布局，不因效果加强重新开布局片。布局修改须先有新增遮挡或输入几何问题的真实red，并保留既有重叠场景作对照；效果更强本身不是布局缺陷证据。

### 派发模板

身份、现场和权限首屏按[交接模板](handoff-template.md)填写；以下补充本片行为与证据，避免只给旧会话名让接手者猜当前职责。

```text
卡片/issue/验收条目：本片消除哪条未验；已有结论与剩余缺口。
行为：触发 → 变化 → 可观察结果；明确本片不承担的剩余项归哪张票。
位置/现场：见交接首屏。
权限/停止边界：见交接首屏；补充本片已核文件/符号、共享注册/文档owner。
依据：目标规格段落、两版API文件；复用证据的准确源码提交/改动范围、目标版本/产物、日志路径及复用失效条件。
依赖：完成了什么才可开始；是否争用同文件或唯一执行者。
验证：复用什么、还缺什么；最小命令/预期case数、失败签名、需扩大覆盖的触发条件；保留独有测试和必要相邻回归。
结束：行为与适用双版证据、审查所需diff；最终提交SHA或明确未提交状态、文件、实际命令和结果、未证范围。
```

恢复/联网片另附一小段expected来源：保存前独立采样→实际存档→新大厅→入房/领取后；对发生变化的字段标明run共享、session或本端profile归属。分别说明恢复正确、独立行为效果、端间一致和前后状态增量；完整DeepEquals不自动证明这四者全部成立。

等待工具链时，另附窄执行委托；一次覆盖分类、归档和已授权的后续验证，失败处理按第4节：

```text
执行者/行为owner：；问题/预期区分的假说：
位置：绝对worktree、源码提交及未提交范围、目标版本/产物。
顺序：逐条命令、工作目录、预期结果；前项失败时哪些后项仍可执行。
边界：可修的工具/夹具文件和具体动作；可继续验证/偶现采样预算；触及何处立即停止回交。
归档：本地原始输出目录；summary按第4节，另记失败分类及证据路径。
回交：约定命令完成、预算耗尽或越界即交结果/剩余问题；确认进程结束及执行权已释放。
```

## 2. 派发顺序：依赖先行，收尾优先

只从依赖已满足且文件所有权明确的Ready卡拉取；没有Ready卡，主控先把一个候选准备成Ready，不盲目并行整票。

优先顺序：

1. 会使现有验证失真的公共宿主/构建/保存缺陷，或阻塞多片的确证问题。
2. 已进入验证、审查、返修或等待集成的片，优先使其流出在制队列。
3. 能消除关键未验、解除更多真实依赖并推动整票验收收口的Ready片；依赖链长的前置工作提前准备。
4. 验收价值和依赖收益接近时，优先避开当前共享热点，再比较风险与完成成本；查看停留过久的卡，不按改动行数挑片。

主控在看板写一句选择理由即可，不建立打分引擎、伪精确工时或自动gate。Boss单一宿主故障只阻塞实际依赖它的行为，不能自动阻塞整张#87或所有其他issue。Holes某片完成后回到批次缺口排序，不因为刚读懂Holes就无限追加邻近测试。

诊断片单独写“本轮能区分的假说、运行预算、捕获什么才继续”。预算结束且没有信息增益时记录证据、撤回临时扰动并挂起，释放执行资源；恢复条件是新证据/新预测，不是“再试三次”。未知根因与已修复明确区分。

## 3. 并发与角色：最多两片在制，按阶段换人

默认活跃WIP最多2片，包含实施、等待执行、审查和等待集成，不能把等待审查移列后偷偷开第三片。阻塞项仍计入WIP；确需释放容量时移为“暂停”，明确恢复条件和保留的改动，停止后台实施。看板同时显示暂停数量，不能靠挂起藏住未完成工作。这个起点可由实际排队/冲突证据调整，不是永久硬上限。

|现场情况|推荐配置（含主控最多四个活跃槽位时）|变化条件|
|---|---|---|
|当前本机，执行请求少|主控兼唯一执行者＋1–2个实施/诊断owner，空余槽位保留|只读研究可临时使用空槽位，问题回答即释放|
|两个Ready片独立，主控执行阻塞协调|主控＋2个开发owner＋1个执行者|测试编写仍由行为owner负责，执行者串行运行并归档，不独自修改oracle|
|某片进入独立双轴审查|主控/唯一执行者＋Standards＋Spec；第四槽按资源情况使用|实施owner先留短状态并结束占槽；返修时复用上下文，审查者不自审|

“2开发＋1测试”作为阶段配置合理，永久常驻不合理：两位开发都等同一执行窗口时应先收尾；进入双轴还要给reviewer留槽。Agent总数不是吞吐量，已创建但空闲的Agent也不等于正在工作的槽位。

所有native/API导出/build/formatter/hooks当前由一个指定执行者串行执行；读已有API、diff和日志可并行。两片都等工具链时，主控明确指定一名执行者并排命令顺序，以一次执行委托连续处理第4节的故障分类、归档和已授权验证，不在每次失败后重新派发。换人前由现任执行者确认现有进程全部结束或终止收回，再交出执行权；空闲槽位不是第二份执行权。

跨issue或职责变化时，新任务使用新的精简上下文；工具支持时以 `fork_turns: "none"` 等实际参数启动，只传首屏入口、目标卡/规格和相关证据指针，按章节/符号窄读，不继承整段旧会话。若工具没有该参数，采用其支持的新上下文机制，不虚构参数；同片返修可保留原owner和相关上下文，无需为每条审查建议重建代理。派发前主控核对当前owner及在制卡，接手后以首屏角色/权限为准，避免沿用旧身份或重复派发。

每个实施者独立worktree，主控独占集成及共享文档；共享注册、session、测试host修改先排所有权。遵守[开发入口](../development.md#并行实施与-worktree)，使用当前工具实际支持的worktree机制，不盲抄其他客户端参数。

## 4. 控制测试成本：每次运行都回答问题

实施owner写行为测试和修改；执行者运行、归档；reviewer读实际diff/源码/证据。审查者不是第三个重复跑测试的人。

|时点|默认范围|允许扩大/重跑的原因|
|---|---|---|
|目标行为未满足或诊断中|最小可复现case/原组，已知失败版优先|新变量、测复现率、验证修复；每次说明预期区分什么|
|片内稳定|适用另一目标版本＋修改影响的消费者/生命周期|共享保存、事件、UI/host、资源、API差异决定相关组合|
|集成后|按现行要求构建和受影响组合|合并/新基改变依赖，或验证当前集成源码|
|发布候选/项目规定批次与hooks|既有完整Check、同提交双版包及人工矩阵|保留现行要求，不能用局部证据替代|

新增测试必须补一个缺失行为或故障模式；已有高层覆盖不能证明低层所有边界，低层绿也不能证明真实transport/UI。选能暴露该错误的最低必要层级；顺序/JIT/恢复问题保留原runner/原生链。测试金字塔不能成为删除真实多端测试的理由。

以下情况不因焦虑重复行为测试：只修改文档；同一源码/依赖/目标已有足够相关证据且没有新的疑点；reviewer换人；主控读日志。记录复用的准确源码提交/改动范围、目标和日志，并逐项说明复用失效条件。资源/运行时/环境变化、修改被测代码或失败尚未解释时重新判断；不能用旧提交全量给当前HEAD签字。复用不取消独有测试、独立双轴审查、必要回归及最终完整检查；局部green只消除对应未验，整票仍按全部验收条件收口。

每次执行先确认命令实际语义：`Test -Branch All`为beta→public、首失败终止，窄filter仍build；资源未变且已有有效PCK才用`-SkipResourceExport`，完整Check按现行导出方式。不要每派一个子片就重启成“新批次”；新批次冒烟仍按开发入口，用户指定的既有诊断续接按其范围运行。

归档只对应实际启动的目标和命令。构建失败后未执行的public写“未运行”，不复制旧last.log。报告命令退出、Build/Host、通过数、Engine/Metadata和原始路径；`ReadTestLog`成功不等于所有字段为0，编译警告另记。完整原始输出留本地，只将失败签名/必要位置送回主控。

失败先分类并归档，再按委托边界继续；未授权的修复交回行为owner，不能把夹具失败当产品red或放宽断言换green：

- 编译/工具准备：先区分环境、依赖与源码错误；执行者只修已授权的本地配置/工具文件，再按委托验证，生产源码编译错误回交owner。
- 夹具不满足原生入口：给出缺失前提和入口证据；只在委托明确的文件/动作内修夹具，超出范围回交owner。
- oracle阶段或归属：记录实际采样阶段、owner/profile及expected来源，回交owner决定；执行者不自行改期望值。
- 真实生产行为：带最小失败签名和调用位置回交owner修复；执行者不擅改生产逻辑。
- 偶现运行条件：仅按委托的新假说、捕获项和采样预算继续；耗尽或无信息增益即回交，不靠重跑取green。临时probe改变调用场时，其green单独标记。

## 5. 用一个Markdown看板管理流动

批次只维护集成树的一份看板，主控是写入者。issue tracker是需求/关闭状态权威；看板是当前本地调度入口；实现文档/日志是证据权威。看板只链接它们，不复制完整时间线，也不在各worktree维护独立进度副本。其他树的旧board副本只作历史，派发必须指向集成树原件。

状态为：Candidate（待准备）→Ready（可派发）→Doing（实施/诊断）→Verify（验证）→Review（审查/返修）→Integrate（待集成）→Integrated（片已合入）。Paused单独列明恢复条件；正式人工验收独立列明所属issue，自动化切片Integrated不关闭整票。Ready至少有验收、文件级brief、真实依赖、owner和最小验证计划。

每卡仅记录：ID/issue、行为、状态、owner/worktree、依赖/热点、下一动作、进入活跃的时间、证据指针。派发、阻塞、发审、集成或暂停时更新；不是每次工具调用都更新。issue汇总保留尚未满足的验收，不用“已完成卡数/总卡数”计算百分比——切片大小和新发现会变。

用现有记录观察WIP、卡片年龄、从开始到集成的周期时间和阶段内完成片数；暂停项也保留原开始时间，避免隐藏滞留。依赖研究和实现片分开看，不混成吞吐量；没有足够同类历史时不承诺SLA或节省比例。token能取得就计全部Agent，不能取得就标不可得，不以日志字数冒充账单。

## 6. 方法依据与适用边界

以下来源于2026-11-14读取的原文；本页选用其方法，不宣称已完成整套Kanban认证或获得量化收益。

- Bill Wake，[INVEST in Good Stories, and SMART Tasks](https://xp123.com/invest-in-good-stories-and-smart-tasks/)：垂直切过各层获得可验证价值、独立/小/可测；项目的API研究可做使能任务，不能冒称完整行为。
- [The Kanban Guide](https://kanbanguides.org/english/)：定义工作流、控制WIP、显式流动规则、WIP/吞吐量/年龄/周期时间。采用拉取与容量控制；本项目暂无足够数据给出概率交付承诺。
- Ham Vocke，[The Practical Test Pyramid](https://martinfowler.com/articles/practical-test-pyramid.html)，Avoid Test Duplication：重复测试有维护成本，高层测试应增加其独有置信度。对本项目意味着保留ENet/原生/UI独有证据，削减无新增信息的重复运行。
- 本项目实证：Holes discovery/roster/profile oracle返工、旧public日志误归档、单执行者未排队及Boss probe扰动，详见批次看板指向的主控记录。理论不代替实际失败条件。
